## 2. 모바일 테스트 플레이 설정 (실행 환경)

### 2.1 저장 형식 — `project.json` → `testplay` (없으면 PC)
```json
{ "env": "phone-port", "custom": { "w": 1080, "h": 2400, "dpi": 400 }, "uiScale": 0, "rotate": true,
  "safeArea": "notch", "insets": { "l": 0, "t": 0, "r": 0, "b": 0 }, "touch": false, "debug": true, "speed": 1 }
```
- `PDM.testEnv.normalize` 가 없거나 틀린 값을 안전한 값으로 바꿉니다: 모르는 환경은 PC, 범위 밖 숫자는 범위 안으로, 배속은 1 · 2 · 4 · 16 중 하나. 고친 칸 이름은 실행 환경 창에 ⚠ 로 보여 줍니다.
- 고치는 곳은 세 군데이고 모두 같은 목록(`ENV_ITEMS`)을 씁니다: 도구 모음의 실행 환경 단추 ▾, 메뉴 **실행 › 실행 환경**, **실행 환경 설정…** 창.

### 2.2 화면 크기 세 가지를 따로 셈 (`editor/renderer/js/testenv.js`)
| 값 | 뜻 | 모바일 세로 예 (1080×2340 · 420dpi) |
|---|---|---|
| 기기 픽셀 (px) | 기기 화면의 실제 점 수 | 1080×2340 |
| 게임 배율 (zoom) | 게임 `PixelScene.create` 와 같은 식: 안전 영역을 뺀 화면에 최소 화면이 들어가는 최대 배율(≥2)과 `ceil(밀도×2.5)` 중 작은 값 | ×7 |
| 논리 화면 (UI 좌표) | 기기 픽셀 ÷ 배율 — 대사창 · 일러스트 · HUD 가 실제로 놓이는 좌표 | 154×334 |
| PC 창 | 논리 화면 × 창 배율(기기 배율의 절반쯤, ≥2) — 큰 휴대폰 화면을 모니터에 맞게 줄이되 배치는 같음 | 462×1002 (×3) |
| 돌린 방향 | 위 네 값을 가로로 다시 셈 (F9) | 2340×1080 → ×6 → 390×180 → 1170×540 |

- 게임 쪽 식이 바뀌면 `run.js` 「실행 환경 계산」 테스트가 실패합니다. 이 테스트는 `PixelScene.java` 의 식과 최소 화면 상수를 직접 읽어 비교합니다.
- PC 의 "UI 배율 자동"은 모니터 밀도에 따라 게임이 정하므로 미리 셀 수 없습니다. 그래서 "자동"이라고만 표시합니다.

### 2.3 게임에 넘기기 · 적용
- 편집기 ▶ 테스트 플레이는 `resolve` 결과를 `game:run` 에 넘깁니다. `editor/playtest-init.js` 가 gradle init 스크립트에 `-Dpdmaker.testenv=<JSON>` 을 넣습니다 (`pdmakerPlaytest` · `desktop:debug` 둘 다). 따옴표와 역슬래시가 섞인 값도 그대로 전달되는지 run.js 로 확인했습니다.
- 런타임 `MakerTestEnv` (실행 환경이 없으면 아무것도 하지 않음 — 일반 실행과 배포 게임은 예전과 같음):
  - 첫 프레임에 인터페이스 크기와 배율을 정하고 창 크기를 바꿉니다. 데스크톱 판의 최소 창 720×400 제한을 풀어야 세로 비율 창이 됩니다.
  - 안전 영역 미리보기: 막힌 곳을 어둡게 칠하고, 대사창과 선택지는 그 안쪽에 놓습니다 (`MakerDialogue.safeArea` 가 기기 값과 시뮬레이션 값 중 큰 쪽을 씀).
  - 터치 표시: 누른 자리에 0.4초 동안 원을 그립니다. 마우스 클릭을 보여 줄 뿐, 실제 터치 입력을 검증하지는 않습니다.
  - 디버그 정보: 환경 이름, 창, UI 크기와 배율, 안전 영역, 배속, FPS. 좁은 세로 화면에서는 줄을 바꿔 보여 줍니다.
  - **F9 화면 돌리기**: 미리 센 돌린 방향과 처음 방향 사이를 오갑니다. 처음엔 창 크기만 뒤집었는데, 그러면 게임이 배율을 다르게 골라(×2, 501×231) 실제 기기 가로(390×180)와 달랐습니다. 두 번 돌리면 안전 영역이 위아래로 뒤집혀 있던 문제도 있었습니다. 둘 다 고쳤습니다.

## 3. 타일 레이어 점검 · 보이기 개선

**조사 결과** (`map.js` 의 4차 상태):
- 레이어는 `world.tileLayers` 의 순서(아래 → 위)와 `depth`(below / above)로 게임에 그려집니다. 편집기 그림 순서도 같았습니다 (지형 → 아래 레이어 → 위 레이어).
- 하지만 편집기에는 **지금 어느 레이어에 그리는지**라는 개념이 없었습니다. 사용자 타일이 기본으로 놓이는 레이어에 그려졌고, 지우개는 별도 선택 칸("전부 · 벽 · 바닥 · 사용자 타일…")이었습니다. 레이어 목록은 접힌 "타일 레이어" 칸에 👁 아이콘만 있었습니다.

**바꾼 것**:
- 레이어 목록을 **위 → 아래** 순서(화면에 보이는 겹침 순서)로 보여 줍니다. 각 줄에 이름, 위/아래 표시, 칸 수, 👁 보이기, 🔓 잠금이 있고, 맨 아래에 「⛰ 지형 · 전체」 줄이 있습니다.
- 한 줄을 누르면 그 레이어가 **편집 대상**이 됩니다. 그리기 도구(펜 · 사각형 · 채우기 · 스포이드 · 지우개 · 선택 영역 복사/붙여넣기)는 그 레이어에만 작용합니다. 방 도구는 지형 전용이라 레이어에서는 꺼집니다.
- 편집 대상은 색만으로 표시하지 않습니다. 줄 테두리와 굵은 이름, 그릴 것 묶음 위의 「칠할 곳: ▦ 레이어 「전경 (캐릭터 위)」」 표시, 도구 툴팁, 상태 줄의 "레이어: …"로 함께 보여 줍니다.
- 「다른 레이어 흐리게」: 고른 레이어만 또렷이 보이고 나머지는 흐려집니다. 데이터는 바뀌지 않고 보기만 바뀝니다.
- 잠근 레이어는 그리기, 지우기, 붙여넣기, 영역 지우기에서 모두 건너뜁니다. 붙여넣기 대상이 잠겨 있으면 알림을 띄웁니다.

## 4. 위 레이어 편집 시 아래 레이어가 지워지던 버그

### 4.1 재현 (4차 코드 `4de5fe2` 에서 실제로 실행 — `$SP/layold.js`)
| 동작 | 기대 | 4차 결과 |
|---|---|---|
| 위 레이어(벽)의 칸을 사용자 타일 지우개로 지움 | 그 칸의 지형이 아래 바닥 타일의 지형(1)으로 | **지형 4(벽)가 남음** — 길이 막힌 채 |
| 지우개(E)로 위 레이어 장식을 지움 | 위 레이어만 지워짐 | 지우개 기본값이 **"전부"** 라서 기본 타일 48 → 46칸, 지형 -1 (아래 레이어까지 지워짐) |
| 영역 복사 · 붙여넣기 | (레이어 개념 없음) | 모든 레이어 + 지형을 한꺼번에 덮어씀 |

### 4.2 원인
1. **지우개 기본값 "전부"**: 레이어에 대한 지우개인데, 기본값이 모든 레이어와 지형을 지우는 항목이었습니다.
2. **지형 재계산 없음**: 칸의 지형은 "그 칸에서 지형을 가진 가장 위 타일"이 정해야 합니다. 그런데 위 타일을 지워도 지형을 다시 정하지 않았습니다.
3. **편집 대상 모델 없음**: 쓰기 경로(그리기, 지우기, 붙여넣기, 영역 지우기, 복사)가 각자 다른 규칙으로 레이어를 골랐습니다.

### 4.3 수정
- 모델은 `ui.target` = `terrain` | `layer` 와 `ui.tileLayer` 입니다. 모든 쓰기 경로가 `onLayer()` · `lockedSet()` · `layerOpts()` 를 거치게 했습니다.
- `PDM.mapArea.retopTerrain(L, i, {terrainOf, order})`: 타일을 바꾸거나 지울 때마다, 그 칸의 지형을 위에서부터 첫 번째로 지형을 가진 타일로 다시 정합니다 (지형 없는 장식 타일은 건너뜀).
- `copy(…, {layer})` 는 그 레이어만 담은 클립(`c.layer`)을 만듭니다. 붙여넣기에서 빈 칸은 "투명"이라 아래를 덮지 않습니다. `clear` 도 레이어 범위로만 지웁니다.
- 지우개 기본값은 편집 대상을 따릅니다 (레이어를 고르면 "지금 레이어").
- 그림 순서(편집기 = 게임)는 이미 같았으므로 바꾸지 않았습니다.

### 4.4 자동 시나리오 — `tools/tests/ui-layers.js` (실제 마우스 · 키보드, 10/10 통과)
1. 아래 레이어에 바닥
2. 위 레이어에 벽과 장식
3. 위 레이어 일부를 지우개(E)로 지움
4. 아래 레이어가 드러나는지 (캔버스 색 · 지형)
5. 위 레이어에 사각형과 채우기
6. 아래 레이어 배열이 그대로인지
7. 레이어 영역 복사 · 붙여넣기
8. 레이어 숨김/표시 (데이터 그대로)
9. 저장 → 다시 열기 (배열 같음)
10. **게임 비교**: 같은 프로젝트를 게임에서 열고(`eval:layercells`), `compare-layers.js` 로 레이어별 칸 → 타일 id와 지형을 편집기 저장 배열과 비교 → **base 48 · wall 11 · front 2 · walldeco 41칸, 지형 48칸 모두 같음**.

**알려진 문제 (원작 게임)**: `Level.updateOpenSpace` 에 테두리 검사가 없습니다. 그래서 손으로 그린 맵의 **가장자리 칸이 지나갈 수 있는 칸**이면, 함정이 터질 때 배열 범위 밖 오류가 납니다. 런타임은 고치지 않았습니다 (원작 코드). 대신 검사(F7)에 「가장자리 칸이 지나갈 수 있음」 경고를 넣었습니다. `MakerTraps` 의 오류 기록에는 처음 몇 줄의 호출 위치를 남겨 원인을 바로 찾을 수 있게 했습니다.

## 6. 대사 글꼴 · 글자 연출

### 6.1 칸 · 단위 (런타임 `EventInterpreter.styleLine` = 편집기 `PDM.Dialogue.styleLine` — run.js 가 두 쪽의 칸 이름과 단위를 비교)
| 칸 | 뜻 | 단위 · 범위 |
|---|---|---|
| `size` | 글자 크기 (대사창 글자 크기 기준) | % · 50~300 |
| `bold` | 굵게 | on / off (빈 칸 = 설정 그대로) |
| `align` | 정렬 | left / center |
| `tracking` | 글자 간격 더하기 | 화면 px · -1~6 |
| `lineGap` | 줄 간격 더하기 | 화면 px · -2~12 |
| `padding` | 대사창 안쪽 여백 | 화면 px · 0~40 |
| `emColor` | 강조(`**…**` · `_…_`) 색 | #rrggbb |
| `speed` | 글자 속도 | instant 0 · slow 20 · normal 40 · fast 80 · **veryfast 160** · 숫자(글자/초) |
| `effect` | 글자가 나타날 때 | none · fade · rise · drop · pop · shake(계속) · wave(계속) |
| `fxDur` · `fxStrength` · `fxScope` | 연출 시간 · 세기 · 범위 | 0.1초 · % · all / em(강조 글자만 = "강조 연출") |

"타자"(한 글자씩)는 `speed` 로, "강조"는 `fxScope: em` 과 강조 색 · 강조 크기 배율(`fx.emScale`)로 만듭니다.

### 6.2 우선순위 — 기본 → 프로젝트 → 이벤트 → 개별 대사
1. **기본값**: `MakerDialogue.DEFAULTS` = `PDM.defaults.dialogue()` (`text.tracking: 0`, `fx: {effect: none, dur: 0.25, strength: 1, scope: all, emScale: 1}`). run.js 가 두 쪽이 같은지 확인합니다.
2. **프로젝트**: 대사창 편집기 (`dialogue.json`) — 글자 간격 · 글자 연출 묶음을 새로 넣었습니다.
3. **이벤트**: 새 명령 **"대사 스타일"(`textStyle`)** — 그 이벤트 안의 다음 대사들에 적용됩니다. `reset` 은 대사창 설정으로 되돌립니다. 다른 이벤트로는 넘어가지 않습니다 (게임 ⑤-0 에서 확인).
4. **개별 대사**: 대사 명령의 글꼴 · 출력 · 연출 탭.

빈 칸은 "다음 단계 값"입니다. **0 은 값**이므로 빈 칸과 구분합니다 (`optnum` 입력 — 비우면 칸 자체를 지움).

### 6.3 편집 UI
- 대사 명령과 대사 스타일 명령의 속성 창 / 큰 창에 탭이 있습니다: **내용 · 글꼴 · 출력 · 연출 · 미리보기**. 명령 종류마다 마지막으로 연 탭을 기억합니다.
- 미리보기는 게임과 같은 계산(`PDM.Dialogue.render`)으로 그 대사를 재생합니다. 앞선 "대사 스타일"까지 반영하고, 아래에 실제로 쓰일 값을 한 줄로 보여 줍니다. 화면 비율은 프로젝트 실행 환경을 따릅니다 (모바일 세로면 세로 상자 — `docs/images/ux5/dialogue-preview-portrait.png`).
- 명령 목록 요약에 바꾼 스타일이 보입니다 (예: `[안내자] …  ✎ 120% · 연출 rise`).

### 6.4 글자 단위 · 한중일 · 타이머
- 글자는 사람이 보는 한 글자(grapheme) 단위입니다. 런타임은 `BreakIterator.getCharacterInstance`, 편집기는 `Intl.Segmenter` 를 씁니다. `👍🏽` 와 `e + ́` 를 쪼개지 않습니다 (run.js · ui-dialogue ⑤).
- 줄바꿈 규칙은 4차의 CJK 수정을 그대로 씁니다: 한중일 글자는 글자마다, 영문 · 숫자 낱말은 빈칸에서 바꿉니다. 편집기도 같은 규칙입니다 (`.dlg-word` 묶음).
- 런타임 버그 수정: 원작 강조 표시 `_` 를 글자로 세어 강조 글자 번호가 하나씩 밀렸습니다.
- **타이머 누수 없음**:
  - 런타임 연출은 대사창 `update()` 안에서 그 창의 시계(`fxT += Game.elapsed`)로만 움직이고, 창과 함께 사라집니다.
  - 편집기 미리보기는 `requestAnimationFrame` 하나로 돌고, 화면에서 빠지면(`isConnected`) 스스로 멈춥니다. 예전 `setInterval` 타자 타이머는 없앴습니다.
  - ui-dialogue ⑥: 재생 중 0.3초에 18프레임이 돌다가, 닫은 뒤 0.5초 동안은 0프레임이었습니다.
- 화면을 돌려 창을 다시 띄우면 예전에는 그 줄을 처음부터 다시 쳤습니다. 지금은 나온 글자 수와 연출 시계를 이어받습니다 (게임 ④-3: 11 → 56 → 61).

## 7. 배속 · 대사 완성 · 다음 대사 · 스킵

| 조작 | 하는 일 | 게임 단추 / 키 |
|---|---|---|
| 배속 1 · 2 · 4 · 16 | `Game.timeScale` (게임 전체 공통 시계 — 이동 · 연출 · 대기 · 글자 · 글자 연출). CSS 가 아니라 게임 시계라서 모든 연출이 같은 비율로 빨라짐 | 1× 2× 4× 16× · F6(돌아가며) |
| 대사 완성 | 지금 대사의 글자와 연출을 바로 끝까지 — 창은 그대로 (입력을 기다림) | 완성 · F7 |
| 다음 대사 | 완성한 뒤 닫음. 선택지가 있으면 선택지를 열기만 함 (사람이 고름) | 다음 · F8 |

**스킵이 끝나는 규칙**:
- 선택지를 열기만 하고 **절대 고르지 않습니다**.
- **입력 기다리기는 그대로 기다립니다**.
- 이벤트가 끝나면 저절로 꺼지고 **스킵 전 배속으로** 돌아갑니다. 다시 누르면 바로 끕니다.
- 실행 중인 이벤트가 없으면 켜지지 않습니다. 기본 창 대사 모드(대사창 "창")에서도 똑같이 동작합니다.

화면 위 가운데의 작은 단추 줄은 고른 배속과 스킵을 **배경 + 아래 줄**로 표시합니다 (색만으로 구분하지 않음). 단추를 눌러도 아래 대사창으로 클릭이 넘어가지 않습니다 (게임 ②: 2× 를 눌러도 대사는 그대로).

### 8.1 보고 받은 충돌 (Windows · 테스트 플레이 시작 직후) — `this.members is null`
- **증상**: 실행 환경을 켠 테스트 플레이가 첫 화면에서 `NullPointerException: … "this.members" is null` (`MakerTestEnv$Overlay$Btn.<init>` ← `Overlay.build` ← `Overlay.update`) 으로 멈춤.
- **원인**: Windows 의 libGDX LWJGL3 는 창 크기를 바꾸는 **그 자리에서** `resize → render` 를 부름. 첫 프레임 `build()` 가 창 크기를 바꾸자 그 안에서 장면이 새로 만들어지며 지금 장면(과 이 Overlay)이 없어졌는데, 돌아와서 없어진 묶음에 단추를 붙임. Linux xvfb 에서는 창 크기 변경이 다음 프레임에 와서 자동 테스트가 잡지 못했음.
- **수정**: 창 크기 · 배율은 그 프레임에서 **그것만** 하고 돌아감(단추는 다음 프레임, 새 장면의 Overlay 가 만듦) · 없어진 Overlay 는 아무것도 하지 않음. F9 화면 돌리기도 같은 이유로 키 처리 중에 바로 하지 않고 다음 Overlay 프레임에서.
- **재현 · 확인**: 하네스에 `SYNC_RESIZE=1`(`-Dpdmaker.testSyncResize=true` — 창 크기를 바꾼 그 자리에서 resize → render, Windows 동작 흉내)을 넣음. 고치기 전 코드 = 같은 NPE 로 멈춤 / 고친 코드 = 창 462×1002 · UI 154×334 ×3 적용, 두 번 돌리기, 대사 정상. `testenv-check.sh` 는 이제 이 방식이 기본이며 11/11 통과 (끈 방식도 11/11). 실제 Windows 에서는 다시 실행하지 않았음 — 보고해 주신 환경에서 확인이 필요함.

## 10. 남은 위험 · 후속 작업
- **실제 기기 · 에뮬레이터 검증이 없습니다**: 터치 입력(멀티 터치 · 길게 누르기), 실제 노치와 펀치홀 모양, 앱 전환과 복귀, 안드로이드 화면 회전 이벤트, 고밀도 화면의 글자 선명도는 확인하지 못했습니다. 2.4 의 표대로 기록해 두었습니다.
- PC 의 "UI 배율 자동"은 모니터마다 달라 미리보기 계산에서 빠집니다.
- 화면 단추는 테스트 플레이 전용(`-Dpdmaker.testenv`)이라 배포 게임에는 나오지 않습니다. 플레이어용 배속 · 스킵이 필요하면 따로 설계해야 합니다 (게임 설정 저장 · 접근성).
- 글자 연출은 글자마다 다른 텍스트 조각이라 아주 긴 대사(수백 자)에서는 그리기 비용이 큽니다. 422자 줄에서 FPS 110~140을 확인했지만 저사양 기기에서는 확인하지 못했습니다.
- 굵게는 원작 글꼴에 굵은 모양이 없어 같은 글을 0.34px 옮겨 겹쳐 그립니다. 편집기 미리보기는 CSS 굵기라 아주 작은 차이가 있습니다.
- 손으로 그린 맵의 가장자리 지나갈 수 있는 칸 + 함정 = 원작 `updateOpenSpace` 범위 밖 오류 (4.4) — 검사 경고로만 알립니다.
- `$SP/layold.js` · `$SP/shift.js` 같은 4차 비교 스크립트는 저장소에 넣지 않았습니다. 그 결과 숫자는 이 문서에 남겼습니다.
