### 발견한 문제

**A. 타일 레이어**
- 레이어에는 사용자 타일만 칠할 수 있었습니다. 사용자 타일은 「맵 그림」 화면에서만 만들 수 있고, 새 프로젝트에는 0개였습니다.
- 그래서 레이어를 골라도 놓을 것이 없었습니다.
- 레이어 편집 중에 지형 타일을 누르면 편집 대상이 몰래 지형으로 바뀌었습니다 (`map.js` `pickTerrain` → `setTarget('terrain')`).

**B. 픽셀(스프라이트) 편집기 창** (`pixel.js`)
- 그림 칸 크기가 캔버스(그림 × 배율)를 따라갔습니다. CSS의 최대 크기는 70vw × 70vh였습니다.
- 창(`.modal`)은 CSS에서 최대 900px이었습니다.
- 모서리(◢)를 `pointerdown` 하는 순간 JS가 창의 `max-width`를 98vw로 바꿨습니다. 그래서 누르기만 해도 창이 커졌습니다.
- 확대/축소도 창 크기를 바꿨습니다.

**C. 캐릭터 AI**
- 방식이 `ai.mode` (fixed · code · patrol …)뿐이었습니다.
- 행동마다 조건 · 우선순위 · 쿨다운을 두는 데이터 방식이 없었고, 공격 종류를 데이터로 정할 수도 없었습니다.
- 원작 `Mob.act`의 `super.act()` 뒤에 있는 연결 줄(`MakerCharAI.act`)이 확장할 자리입니다.

**D. 공격 모션**
- `attackFx`는 1판이었습니다. `keys [[t, 각도, 거리, 크기, 불투명도]]`에 smoothstep 하나, 타격 시각, 휘두름 · 맞는 순간 이펙트만 있었습니다.
- 그림만 그리고 판정 시각과는 맞추지 않았습니다.
- 속성마다 따로 두는 키프레임, 이징, 같은 타임라인의 이펙트가 없었습니다.

### 계획 (사용자 지정 순서)

각 단계는 편집 → 저장 → 실행 → 확인을 한 번에 끝내는 조각으로 진행했습니다.

1. 타일
2. 스프라이트 창
3. AI · 전투 모델
4. AI 편집기 + 런타임
5. 모션 타임라인 + 이펙트
6. 저장 · 오류 · 실행 취소 통합
7. 테스트
8. 게임 확인
9. 문서

AI와 모션은 7차 타이틀과 같은 방식을 썼습니다.
- 순수 JS 모델과 순수 Java 모델이 같은 규칙을 가집니다.
- `run.js`가 Java를 javac로 실행해 같은 입력의 결과를 비교합니다.
- 그래서 미리보기 · 시뮬레이터와 게임이 같은 규칙으로 움직인다는 것을 테스트로 보장합니다.

## 2. A — 레이어 타일 추가 · 배치

### 바뀐 파일

| 파일 | 내용 |
|---|---|
| `editor/renderer/js/layertiles.js` (새) | `PDM.layerTiles` — 순수 함수 |
| `editors/map.js` | 레이어 편집 중 팔레트 · 레이어 전체 지우기 · 정의 없는 칸 ✕ · 타일 불투명도 그리기 |
| `runtime/.../MakerUserTiles.java` | 사용자 타일 `alpha` |
| `css/app.css` | 팔레트 스타일 |

`PDM.layerTiles`가 하는 일은 다음과 같습니다.
- 목록 보기
- 타일셋 영역 가져오기 (같은 칸이면 이미 있는 타일을 다시 씀)
- 복제 · 순서 · 목록에서 빼기 · 삭제
- 쓰는 곳 세기 · 검사

### 데이터 (기존 형식에 더하기만 함)

- `world.tileLayers[].tiles: [타일 id…]` — 그 레이어에 놓을 타일 목록이며 팔레트 순서입니다.
  - 목록이 없는 레이어(예전 프로젝트 · 기본 레이어)는 모든 사용자 타일을 보여 줍니다.
  - 어느 레이어든 처음 고칠 때, 모든 레이어를 "지금 보이던 목록"으로 만들어 저장합니다. 그래서 새 타일은 고친 레이어에만 들어갑니다.
  - 런타임은 이 목록을 쓰지 않습니다. 칸마다 적힌 타일 id를 그대로 그리므로, 목록에서 빼도 이미 놓은 칸은 바뀌지 않습니다.
- `world.userTiles[].category` — 분류. 팔레트에서 걸러 보는 데만 씁니다.
- `world.userTiles[].alpha` (0~1) — 게임에서 그 타일의 불투명도입니다 (`MakerUserTiles.render`).
- 타일셋에서 가져온 타일은 그림을 복사하지 않습니다. `image`(그림 경로) + `x`, `y`(칸) + `size`(칸 크기)를 가리킵니다.

### 쓰는 법 (맵 그리기)

1. 왼쪽 「② 타일 레이어」에서 레이어 줄을 누릅니다.
2. 「① 그릴 것」이 그 레이어의 타일 목록으로 바뀝니다.
   - 썸네일, 찾기, 분류 걸러 보기, 최근 사용이 있습니다.
   - 지형 타일 격자는 숨겨집니다. 지형을 그리려면 「⛰ 지형 편집으로」 버튼을 누르거나, 레이어 목록의 "지형 · 전체" 줄을 누릅니다. 대상이 저절로 바뀌는 일은 없습니다.
3. 타일을 추가합니다. 목록이 비었으면 이 세 버튼이 바로 보입니다.
   - **▦ 타일셋에서 가져오기**: 이 맵 테마의 타일셋이 칸 격자로 열립니다. 끌어서 여러 칸을 고르거나, 화살표 · Shift+화살표로 고릅니다. 이름 · 분류 · 칸 크기를 정하면 칸마다 타일이 하나씩 생깁니다.
   - **⤓ 이미지 가져오기**: PNG를 `assets/tiles`로 가져온 뒤 같은 칸 고르기 창이 열립니다.
   - **✎ 새로 그리기**: 16×16 그림을 픽셀 편집기로 그려 `assets/tiles/utile_<id>.png`로 저장합니다.
   - **다른 타일 (n)**: 다른 레이어용으로 만든 사용자 타일을 이 레이어 목록에도 붙입니다.
4. 추가하면 첫 타일이 골라진 상태가 됩니다. 펜 · 사각형 · 채우기 · 스포이드 · 영역 선택 · 복사/붙여넣기를 바로 쓸 수 있습니다. 모두 기존 도구이고, 대상은 지금 레이어뿐입니다.
5. 타일을 고르면 아래 칸에서 다음을 할 수 있습니다.
   - 이름 · 분류 · 불투명도 고치기
   - ◀ ▶ 순서 바꾸기
   - 복제 (확인 창을 거침)
   - ↻ 그림 다시 읽기
   - 자세히… (「맵 그림」 화면)
   - 삭제
6. 놓인 타일을 삭제하면 쓰는 곳(맵 · 칸 수)을 먼저 알려 줍니다.
   - "목록에서만 빼기"를 고르면 칸은 그대로입니다.
   - "삭제"를 고르면 정의만 지웁니다. 칸의 id는 남고 맵에 ✕로 표시됩니다. 게임에서는 그려지지 않고 경고 한 번만 남깁니다. 다른 그림으로 조용히 바뀌는 일은 없습니다.
   - 둘 다 실행 취소로 되돌릴 수 있습니다.
7. 「이 레이어 전체 지우기…」는 확인 창을 거친 뒤 그 레이어만 지웁니다. 지형은 남은 레이어에 맞추고, 실행 취소가 됩니다.
8. 검사 표시 (빨간 점선 테두리 + 툴팁 ⚠)
   - 그림을 찾을 수 없는 타일
   - 칸이 그림 밖인 타일
   - 목록에 있지만 정의가 없는 id ("목록 정리" 버튼)
   - 정의가 없는 타일이 놓인 칸 수

레이어 숨김 · 잠금 · 다른 레이어 흐리게 · 아래 레이어 보존은 5차 동작 그대로이며 회귀 테스트로 확인했습니다.

## 3. B — 스프라이트(픽셀) 편집기 창 크기

### 원인

§1에 적은 두 가지입니다.
- 모서리를 누르면 JS가 창 `max-width`를 900px에서 98vw로 바꿨습니다.
- 그림 칸 크기가 캔버스 크기를 따라갔습니다.

### 수정 (임시 오프셋 · 강제 새로고침 없음)

- CSS가 처음부터 창 규칙을 정합니다: `.modal:has(.px-wrap) { max-width: 98vw; max-height: 96vh }`.
- 그림 칸 크기도 처음부터 정합니다: `.px-pane { width: clamp(160px, 98vw − 420px, 720px); height: clamp(120px, 96vh − 210px, 640px) }`.
  - 화면 크기로만 정하고, 그림 · 배율과는 상관없습니다. 캔버스는 그 안에서 스크롤합니다.
  - 미리보기 칸이 있으면 그만큼 뺍니다.
  - 좁은 화면(≤720px)에서는 도구 칸을 그림 아래로 보냅니다.
- 모서리 끌기는 그림 칸의 `width`/`height`만 바꿉니다. 창 스타일은 건드리지 않습니다.
  - 최대값은 지금 창에서 그림 칸 밖의 부분을 뺀 화면 크기입니다.
  - 두 번 누르면 CSS 크기로 돌아갑니다.
- 그리기 · 선택 · 실행 취소 · 저장은 그대로입니다.

### 회귀 테스트 `tools/tests/ui-sprite-window.js`

크기를 재는 때는 다음과 같습니다.
- 열 때, 즉 창이 DOM에 붙는 순간 (MutationObserver)
- 첫 그리기 뒤, 0.5초 뒤
- 모서리를 누름 · 뗌
- 확대(+ · Ctrl+휠 · 배율 1 · 40)
- 끌기 · 두 번 누르기
- 다시 열기 · 탭 바꾸기 · 512×512 그림 · 800×560 작은 화면

크기는 레이아웃 크기(offsetWidth)로 잽니다. 창이 나타나는 0.2초 애니메이션의 transform은 빼고 봅니다.

| 시점 | 수정 전 | 수정 후 |
|---|---|---|
| 결과 | 11개 중 7개 실패 | 11 통과 |
| 모서리 누름 | 창 900×792 → 1294×864 | 창 1372×864 그대로 |
| 확대 | 창이 바뀜 | 캔버스만 384 → 1280 |

## 4. C — 캐릭터 AI · 공격 설정

### 구조

| 파일 | 내용 |
|---|---|
| `editor/renderer/js/aimodel.js` (새) | `PDM.aiModel` — 정리 · 고르기 · 다음 상황 · 턴 · 검사 |
| `runtime/.../MakerAIModel.java` (새) | 같은 규칙 (게임 라이브러리 없음) |
| `runtime/.../MakerCombat.java` (새) | 상황 만들기 → 고르기 → 실제 이동 · 공격 · 저장 |
| `MakerCharAI.java` | 연결 줄 (아래 참고) |
| `editors/charcombat.js` (새) | AI · 전투 편집기 (탭 `combat:<캐릭터 id>`) |
| `editors/character.js` | "AI · 경로" 칸에 요약 + 여는 버튼 |
| `validate.js` | F7 검사에 포함 |

`MakerCharAI.java`의 연결 줄은 다음과 같습니다.
- `act`: `combat`이 있으면 MakerCombat이 먼저 처리하고, `null`이면 원래 방식으로 갑니다.
- `afterDamage`: 사건 hit.
- `preventDeath`: 쓰러질 때 행동.
- `store`/`restore`: 저장 · 불러오기.

### 데이터

`characters/<id>.json`에 `combat`이 붙습니다. 원래 데이터는 그대로입니다.

```
combat { version: 1, enabled, detect(감지 거리 칸), debug, behaviors: [...], attacks: [...] }
```

**행동** `{ id, name, enabled, priority, on, when, action, attack, target, dist, amount, say, cooldown, delay, chance, weight, next, fail, interrupt }`

| 칸 | 값 |
|---|---|
| `on` | `''` 평소 · `hit` · `attacked` · `targetLost` · `death` |
| `action` | attack · approach · retreat · keep(거리 유지) · flee · wander · patrol(처음 자리 둘레) · wait · heal · protect(아군 곁으로) · say · default(원래 AI) |
| `target` | enemy(게임이 고른 적) · hero · nearestEnemy · weakestEnemy · weakestAlly · self |

**조건** `when`
- 묶음: `{ op: and|or, not, items }`
- 하나: `{ k, cmp, v, not }`
- `k`의 종류: hp% · targetHp% · dist · visible · line(투사체가 닿음) · hasTarget · chance% · turn · event · allies · enemies · status · targetStatus · ready(공격 쿨다운 끝)

**공격** `{ id, name, type: melee|ranged|area, range, radius, windup, recovery, mult, flat, acc, crit, critMult, hits, cooldown, hpCost, knockback, stun, status, statusTurns, filter, friendlyFire, projectile, anim, effect, sound }`

### 고르는 규칙 (편집기 · 시뮬레이터 · 게임 공통)

1. 우선순위가 높은 것부터 검사합니다. 같은 우선순위는 목록 순서로 검사합니다.
2. 행동마다 다음을 차례로 봅니다.
   1. 꺼짐
   2. 사건
   3. 행동 쿨다운
   4. 대상
   5. 조건
   6. 공격이면: 공격이 있는지 · 공격 쿨다운 · 사거리 · 투사체가 닿는지 · 체력 소모
   7. 확률
3. 통과한 것 중 가장 높은 우선순위 묶음에서 가중치로 하나를 고릅니다.
4. 이어서 할 행동(성공 뒤 `next` · 실패 뒤 `fail`)은 우선순위와 상관없이 맨 먼저 검사합니다.
5. 난수는 조건 확률 → 행동 확률 → 가중치 순서로 씁니다.
6. 시간은 모두 게임 턴입니다.
   - 게임 쪽 시계는 `Statistics.duration + Actor.now()`입니다. 저장할 때 원작이 `Actor.fixTime()`으로 시간을 다시 맞추더라도 쿨다운이 이어집니다.

### 게임에서의 실행 (MakerCombat)

**공격**
- 명중은 `Char.hit(자신, 대상, acc)`입니다. 범위 공격은 늘 맞습니다.
- 피해는 `round(damageRoll × mult + flat)`(치명이면 × critMult) − 대상 `drRoll`입니다. 원래 공격과 같은 방어 계산이며, hits 번 반복합니다.
- 준비(windup)가 있으면 머리 위에 "!"를 띄우고 그 턴만큼 기다린 뒤 공격합니다. `interrupt`가 켜져 있으면 준비 중에 맞을 때 끊깁니다.
- 회복(recovery) · 대기(delay)만큼 턴을 더 씁니다.
- 동작은 캐릭터 스프라이트의 `attack`/`zap`이고, 원거리는 마법 화살이 날아갑니다.

**효과**
- 밀치기: `WandOfBlastWave.throwChar`
- 기절: `Paralysis`
- 상태: 게임 버프 10종

**안전장치**
- `combat`이 없는 캐릭터는 원래 AI 그대로입니다.
- 꺼짐 · 검사 오류 · 읽기 실패이면 원래 AI로 움직이고, 게임 안 경고 한 번과 로그를 남깁니다. 게임은 멈추지 않고 프로젝트도 고치지 않습니다.
- `combat.debug`가 켜져 있으면 차례마다 다음 줄을 남깁니다.
  ```
  [PDMaker] [AI] <id> t=… hp=… → 고른 행동 (동작 공격) 이유=… | 행동=이유 …
  ```
  런타임이 설정을 실제로 쓰고 있다는 디버그 정보입니다.
- 저장: 쿨다운(게임 시간) · 이어서 할 행동을 몬스터와 함께 저장합니다. 준비 중인 공격과 사건은 저장하지 않으며, 불러오면 다시 판단합니다.

### 데이터 — `attackFx`, 1판 그대로 + 2판 칸을 더함

| 칸 | 내용 |
|---|---|
| `tracks { angle, dist, scale, alpha, ox, oy: [[t, 값, 이징]] }` | 속성마다 따로인 키프레임. 있으면 `keys` 대신 씁니다 |
| 이징 | smooth(1판과 같음) · linear · in · out · inout · step · back |
| `ox` · `oy` | 바라보는 쪽 기준 앞 · 옆 px. 왼쪽을 보면 옆이 뒤집힙니다 |
| `hits [t]` | 타격 시각 |
| `hitWindows [[t0, t1]]` | 판정 구간. 없으면 타격 시각마다 한 점 |
| `segments { windup, hit, recovery }` | 시작 · 준비 · 타격 · 회복 표시 |
| `sync: 'game'` | 원작대로, 공격 동작이 끝날 때 판정 |
| `sync: 'hit'` | 첫 타격 시각에 판정. 그 공격에만 게임 공격 동작의 한 칸 시간을 `첫 타격 초 ÷ 칸 수`로 바꿉니다. 다음 공격이나 모션 없는 무기는 원래 값입니다 |
| `events [{ id, type, t, dur, anchor, dir, size, alpha, ease, ref, every, power, grow, role }]` | 같은 타임라인의 이펙트 |

이펙트 종류(`type`)는 다음과 같습니다.
- effect (effects.json)
- flash (맞는 번쩍임)
- shake (화면 흔들기 — 기존 `MakerCamera.shake`)
- sound
- trail (잔상)
- shock (충격파)
- image (그림 — 불투명도 · 크기가 이징으로 변함)
- projectile

`role: 'hit'`은 맞는 순간 이펙트라는 표시입니다. 판정 구간 밖에 있으면 검사에서 알립니다.

**시간 기준**
- `t`는 0~1(모션 한 번)입니다.
- 초 = `t × (dur ÷ speed)`이며, 게임의 `Game.elapsed` 초와 같은 기준입니다.
- 프레임 = 초 × 60 (반올림). 화면 60fps 기준이며 표시용입니다.
- 원작 영웅 공격 동작은 4칸 × 1/15초이고, 마지막 칸 뒤 한 칸 시간이 더 지나야 끝납니다. 그래서 0.267초 뒤에 판정합니다.

**검사**
- 키프레임 없음 · 음수 · 0~1 밖
- 여러 타격 — 게임 판정은 공격 한 번에 한 번이라고 알립니다.
- **그림은 나오는데 판정이 없음** — 맞는 순간 이펙트가 판정 구간 밖에 있는 경우
- 첫 타격과 게임 판정이 0.06초 넘게 어긋남 · 판정 맞추기를 골랐는데 타격이 없음 · 판정이 모션이 끝난 뒤
- 이펙트의 그림 · 소리가 비어 있음

### 게임에서의 실행 (MakerSwing)

- 모든 것이 끝나면 스스로 지웁니다.
  - 화면이 바뀌면 화면과 함께 지워지고, 남은 그림과 흔들림 소유도 함께 정리합니다.

  - 여러 번 공격해도 쌓이지 않습니다.
- 모션이 없는 무기는 원작 그대로이며, 공격 동작 길이도 원래 값으로 돌려놓습니다.
- 데이터가 잘못되면 그 공격만 모션 없이 진행하고 경고 한 번을 남깁니다. 게임은 멈추지 않습니다.

## 7. 확인하지 못한 것 · 제한사항 · 후속 과제

### 실제 기기 · 플랫폼

- 안드로이드 · iOS 실제 기기에서는 확인하지 않았습니다.
- 모든 게임 확인은 데스크톱 판(LWJGL3)을 Xvfb에서 돌린 것입니다.
- Electron 편집기 자체는 띄우지 않았습니다. 같은 렌더러 코드를 웹 모드(Chromium)로 확인했습니다.

### 타일

- 회전 · 뒤집기는 지원하지 않습니다. 런타임 타일맵(`Tilemap`)이 칸마다 회전 · 뒤집기를 할 수 없습니다. 지원하는 배치 속성은 불투명도뿐입니다.
- "타일셋에서 가져오기"는 그 맵 테마의 타일셋만 엽니다. 다른 그림은 "이미지 가져오기"로 엽니다.
- 칸이 그림 밖인지 검사하는 것은 팔레트에서만 합니다 (그림을 불러와야 크기를 앎). F7 전체 검사는 그림 파일이 있는지만 봅니다 (기존 에셋 검사).
- 레이어 목록(`tiles`)은 편집기 팔레트용입니다. 런타임은 목록과 상관없이 칸에 적힌 타일을 그립니다 — 의도한 동작입니다.

### AI · 전투

- 자원은 체력 소모(`hpCost`)만 지원합니다. 원작에 마나 · 기력이 없기 때문입니다.
- 공격 판정은 동작이 끝날 때입니다. 프레임 단위 판정은 없습니다.
- 휘는 투사체 · 회전 투사체는 없습니다. 원거리는 마법 화살 모양 하나이고 명중은 즉시입니다.
- 공격 이펙트의 크기 · 방향은 effects.json 이펙트 설정을 따릅니다.
- "순찰"은 처음 자리 둘레 4칸을 돌아다니는 것입니다. 경로 순찰은 기존 `ai.mode: patrol`을 씁니다.
- 아군 보호는 "아군 곁으로 가기"까지만 합니다. 대신 맞아 주기는 없습니다.
- 사건은 hit · attacked · targetLost · death입니다. "아군이 맞음"은 없습니다.
- 준비 중인 공격 · 사건은 저장하지 않습니다. 불러오면 그 차례를 다시 판단합니다.
- NPC(MakerNPC)도 같은 연결 줄을 지나지만, 게임 확인은 몬스터(MakerMob)로만 했습니다.

### 공격 모션

- 무기 그림은 한 장(아이템 그림)입니다. 프레임마다 다른 그림은 없습니다.
- 이펙트의 크기 · 방향 · 불투명도는 "그림" 이펙트에만 적용됩니다. effects.json 이펙트 · 충격파 · 투사체는 각자 설정대로입니다.
- 게임 판정은 공격 한 번에 한 번입니다. 두 번째 타격부터는 그림 · 이펙트만 나옵니다 (검사에서 알림).
- 판정 맞추기는 영웅 공격 동작 길이를 바꾸는 방식입니다. 게임 턴 소모(공격 속도)는 바뀌지 않습니다.
- 캐릭터(몬스터)의 공격 모션 · 캐릭터 공격과의 프레임 동기화는 영웅이 든 무기만입니다. 몬스터 공격 동작은 C의 `anim`(attack · zap)을 씁니다.
- 소리 이펙트는 게임 소리 경로 문자열을 직접 적습니다. 시험 환경이 NOMP3라 소리는 실제로 듣지 못했습니다.

### 후속 과제

- 레이어 타일의 칸 단위 회전 · 뒤집기: 레이어 렌더러를 Image 묶음으로 바꾸는 큰 작업입니다.
- AI 시뮬레이터에서 여러 대상 · 지형(벽 · 시야)을 다루기: 지금은 거리 · 보임 · 투사체를 값으로 넣습니다.
- 몬스터 공격의 타임라인 모션.
