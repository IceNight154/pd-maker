# PDMaker 기술 평가 · 개선 기록 (2026-10-17)

게임 메이킹 엔진으로서 PDMaker 를 평가하고, 확인된 문제를 우선순위대로 고친 기록입니다.
**확인됨** = 테스트 · 실행으로 재현함 / **코드 확인** = 코드를 읽어 원인을 특정했으나 실행으로 재현하지 않음 / **의심** = 측정 · 재현이 필요함.

## 0. 조사 범위

| 범위 | 한 일 |
|---|---|
| 편집기 (`editor/renderer/js` 67개 파일 · 약 2.3MB) | 저장 · 불러오기(`store.js`), 변환(`schema.js`), 검사(`validate.js`), 맵 편집기(`editors/map.js`), 조합 타일(`editors/combos.js`), 그림(`assets.js`)을 읽음. 나머지 편집기(영웅 · 아이템 · 대사 · 타이틀 …)는 구조만 훑음 |
| 편집기 프로세스 (`editor/main.js` · `preload.js` · `bridge.js`) | 파일 쓰기 · 내보내기 · 복사 경로 |
| 런타임 (`runtime/…/pdmaker` 74개 Java 파일) | 타일 레이어 · 사용자 타일 · 밑그림 · 조합 · 함정 · 광원 연결부(`MakerTileLayers` · `MakerUserTiles` · `MakerTileUnderlay` · `MakerCombos` · `MakerTraps` · `MakerLights` 일부) |
| 게임 소스 (`game/shattered-pixel-dungeon-master`, SPD 4.0.0) | `DungeonTileSheet`(타일 번호) · `levels/traps` · `Tilemap`/`SmartTexture` · `Game.switchScene` |
| 실행 | Node 회귀 테스트(신규), javac 로 게임 + 런타임 컴파일, Xvfb 헤드리스 게임 실행(`tools/playtest`) |
| **못 한 것** | Electron 편집기 화면을 직접 조작하는 UI 테스트, Windows 실행, 안드로이드 빌드(이 환경에서 Android Gradle 플러그인 다운로드가 막힘), 성능 측정 |

## 1. 총평

**수준: "데이터 기반 모드 제작 도구"로서는 완성도가 높고, "범용 게임 메이킹 엔진"으로는 중간 단계.**

근거 (강점):
- 편집 데이터(프로젝트 폴더 JSON · PNG)와 실행 코드(런타임)가 분리되어 있고, 게임 원본은 연결 줄(`runtime-installer.js PATCHES`)로만 건드림 → 게임 판(2.5 ~ 4.0)이 바뀌어도 데이터는 그대로.
- 이번 작업 이전 커밋들(`38140b7` ~ `bbe8ce4`)에서 요구사항의 핵심 구조가 이미 들어가 있었음: 지형(판정) ↔ 사용자 타일 레이어(그림) ↔ 오브젝트(함정 등) 분리, 데이터로 추가하는 레이어, 조합 타일 프리셋(편집 · 복제 · 삭제 · 자동 생성 등록), 투명 배경 타일셋의 밑그림 재현. 이번에 헤드리스 게임으로 다시 확인함(§8).
- 모든 편집이 `store.edit` 한 곳을 거쳐 실행 취소 · 저장 표시가 일관됨.

근거 (한계):
- **저장 안전성에 데이터 손실 경로가 있었음** (P0 4건 — 이번에 고침).
- **거대한 단일 파일 · 전역 이름 공간**: `editors/map.js` 153KB(팔레트 · 도구 · 레이어 · 오브젝트 · 계단 · 인스펙터 · 그리기를 한 함수 안에서), `app.js` 97KB, `tools/playtest/Hooks.java` 105KB. 70개 가까운 스크립트가 `window.PDM` 에 붙고 `<script>` 순서에 의존. 새 기능을 넣을 때 이 파일들을 넓게 고쳐야 함.
- **편집기 ↔ 런타임 중복 정의**: 같은 표(밑그림 대응표 · 구멍 · 기본 레이어 · 함정)를 JS 와 Java 에 두 번 씀 — 지금까지는 주석으로만 "같음"을 약속. 이번에 테스트로 묶음(§8), 하나의 원본에서 만들어 내는 구조는 아님.
- **이번 작업 전에는 자동 회귀 테스트가 없었음** (헤드리스 플레이 도구는 있었지만 의존 jar 를 손으로 준비해야 함).
- 맵 편집기의 반복 작업 도구가 약함: 오브젝트 단일 선택, 타일 영역 복사/붙여넣기 · 일괄 수정 없음.

## 2. 주요 문제점

각 항목: 위치 · 근거 · 원인 · 영향 · 그대로 두면 · 해결 · 수정 범위 · 검증.

### P0 — 데이터 손실

**P0-1 손상된 `maps/world.json` → 기본 맵 그래프로 바뀌고 멀쩡한 노드 파일까지 덮어씀** — 확인됨 · 고침
- 위치: `store.js load` (단일 파일 읽기 실패 처리)
- 근거: 테스트 "손상된 JSON 파일"이 수정 전 실패 — "world.json 이(가) **없어서** 기본값으로 만들었습니다"라고 잘못 알리고, 기본 노드(`n1`…)를 저장 대상으로 표시.
- 원인: "파일 없음"과 "파일 손상"을 같은 `catch` 에서 처리.
- 영향/위험: 쓰다 만 파일 하나로 맵 그래프(그룹 · 연결 · 사용자 타일 · 레이어 · 사용자 테마)가 저장과 함께 사라지고, 같은 id 의 노드 맵이 기본 맵으로 바뀔 수 있음.
- 해결: 존재 여부를 먼저 확인. 손상이면 기본값으로 열되 저장 대상으로 표시하지 않고, 기본 노드를 만들지 않음. 그 항목을 고쳐 저장할 때 손상본을 백업한 뒤 덮어씀. 문구도 "손상되어 읽지 못했습니다"로.
- 범위: `store.js` 한 곳. 검증: 테스트 2개(손상 파일 · 고쳐 저장).

**P0-2 손상된 단일 파일(타이틀 · 대사창 · 이펙트 · 조합 타일 …)이 알림 없이 기본값으로 바뀌어 덮어써짐** — 확인됨 · 고침
- 근거: 같은 테스트에서 `title.json` 손상 알림이 없었음(알림 제외 목록에 들어 있음). 원인 · 해결은 P0-1 과 같음.

**P0-3 저장할 때 지울 파일을 먼저 지움 → 쓰기가 실패하면 옛 데이터도 새 데이터도 없음** — 확인됨 · 고침
- 위치: `store.js save`
- 근거: 테스트 "저장 중 쓰기 실패" — 수정 전에는 쓰기가 실패했는데 예전 형식 파일(`floor_XX.json`)이 이미 지워져 있었음. 지울 목록도 먼저 비워져 다시 저장해도 복구 안 됨.
- 영향: 예전 형식(5층 단위 장) 프로젝트를 변환해 저장하다 디스크 · 권한 문제가 나면 맵 데이터 전체 손실. 이름 바꾸기 · 삭제도 같은 순서.
- 해결: 백업 → 쓰기(하나씩 성공한 것만 "저장됨") → 다 쓴 뒤 지우기. 실패하면 예외와 함께 남은 항목은 "저장 안 됨"으로 남음.
- 검증: 쓰기 실패를 흉내 낸 테스트, 이름 바꾸기 저장 테스트.

**P0-4 형식 변환 전 원본 백업 없음** — 확인됨 · 고침
- 위치: `store.js load` 의 변환들(맵 `utile` → 레이어, 지형 함정 → 오브젝트, 스킬 → 주문, 예전 맵 형식 → 그래프, 마음의 보석, 조합 `combos` → `list`, 캐릭터 "영웅" → 영웅)
- 근거: 테스트 "예전 형식 변환 저장"이 수정 전 실패(백업 0개).
- 해결: 변환한 키 · 손상 키 · 지울 파일은 저장 직전 `.pdmaker-backup/<시각>/<같은 경로>` 로 복사(처음 한 번). 최근 20개 폴더만 남김. 게임 내보내기 · 프로젝트 내보내기 · 다른 이름으로 저장에는 넣지 않음(`main.js skipProj`).
- 복구 절차: 백업 폴더의 파일을 같은 상대 경로로 되돌려 놓고 프로젝트를 다시 열기.

### P1 — 구조

**P1-1 조합 타일의 광원이 세이브에 남지 않음 → 조합을 고치거나 지우면 이미 만든 층의 빛이 바뀜/사라짐** — 확인됨 · 고침
- 위치: `MakerCombos.lights` (세이브에는 조합 id · 칸만 저장, 광원은 불러올 때 지금 정의에서 찾음)
- 근거(헤드리스 게임): 수정 전 런타임 — 새 게임에서 벽면 광원 조합 9곳 · 광원 9개 → 저장 → 조합의 광원을 끔 → 이어하기 → **광원 0개**. 수정 후 — 7곳 · 7개 → 같은 절차 → **7개 그대로**. (그림 · 오프셋은 원래도 `MakerUserTiles` 에 구워져 유지됨.)
- 원인: 문서(DESIGN §4.2.2)의 "이미 만든 층은 그대로" 정책과 구현이 어긋남.
- 해결: 놓을 때 광원 설정 JSON 을 `pdm_combo_lights` 로 복사. 복사본이 없는 예전 세이브는 지금 정의에서 찾음(이전 동작) — 예전 세이브를 새 런타임으로 이어하기 → 광원 9개, 다시 저장 · 이어하기 → 9개(호환 확인).

**P1-2 편집기 · 런타임에 같은 표를 두 번 정의** — 코드 확인 · 테스트로 묶음
- 위치: `schema.js` `TILE_LEGACY_DEFAULT` · `TILE_HOLES` · `TILE_LAYERS_DEFAULT` · `TRAPS`/`TRAP_LEGACY` ↔ `MakerTileUnderlay.LEGACY/HOLES` · `MakerTileLayers.DEFAULT` · `MakerTraps`
- 위험: 한쪽만 고치면 편집기 미리보기와 게임 화면이 어긋남(미리보기 ≠ 실제).
- 이번 조치: `tools/tests/run.js` 가 두 정의와 게임 소스를 비교(현재 모두 일치). 후속: 한 JSON 에서 둘을 만들어 내기.

**P1-3 거대 파일 · 전역 상태** — 코드 확인 · 고치지 않음 (위험 대비 효과)
- `editors/map.js` 의 `render` 한 함수 안에 상태 `ui` · 팔레트 · 도구 · 레이어 창 · 오브젝트 메뉴 · 계단 연결 · 인스펙터 · 그리기가 클로저로 얽혀 있음. 기능 하나를 고칠 때 1,500줄 문맥이 필요하고, 다른 편집기에서 맵 그리기를 재사용하기 어려움(조합 편집기는 미리보기를 따로 구현).
- 권장: 동작을 바꾸지 않는 단계적 분리 — ① 그리기(`paint` · `drawLayer`)를 순수 함수 모듈로 ② 오브젝트 메뉴 · 인스펙터 ③ 레이어 창. 각 단계마다 회귀 테스트(웹 모드 + Playwright 화면 비교)를 먼저 마련.

**P1-4 자동 회귀 테스트 부재** — 확인됨 · 일부 해결
- `tools/tests/` (Node 만 필요) 추가. 헤드리스 게임 실행은 여전히 jar 준비가 필요(§8 에 명령 기록).

## 3. 유지한 기능 (동작 · 형식 그대로)

- 프로젝트 파일 형식 · 리소스 키 · 경로 — 바뀐 것 없음 (`.pdmaker-backup/` 폴더만 새로 생길 수 있음).
- 보존 대상 타일 번호 29종 `1, 2, 3, 7, 8, 9, 16, 18, 22, 64, 65, 66, 67, 69, 70, 72, 73, 74, 75, 120, 121, 122, 123, 125, 126, 128, 129, 130, 131` — 번호 · 밑그림 대응(0 바닥 · 6 바닥 변형 · 4 특수 바닥) 그대로. 게임 `DungeonTileSheet` 와 대응 확인: 1 FLOOR_DECO · 2 GRASS · 3 EMBERS · 7 FLOOR_DECO_ALT · 8 GRASS_ALT · 9 EMBERS_ALT · 16 ENTRANCE · 18 WELL · 22 ENTRANCE_SP · 64 FLAT_ALCHEMY_POT · 65 FLAT_BARRICADE · 66 FLAT_HIGH_GRASS · 67 FLAT_FURROWED_GRASS · 69 FLAT_HIGH_GRASS_ALT · 70 FLAT_FURROWED_ALT · 72 FLAT_STATUE · 73 FLAT_STATUE_SP · 74 FLAT_REGION_DECO · 75 FLAT_REGION_DECO_ALT · 120 RAISED_ALCHEMY_POT · 121 RAISED_BARRICADE · 122 RAISED_HIGH_GRASS · 123 RAISED_FURROWED_GRASS · 125 RAISED_HIGH_GRASS_ALT · 126 RAISED_FURROWED_ALT · 128 RAISED_STATUE · 129 RAISED_STATUE_SP · 130 RAISED_REGION_DECO · 131 RAISED_REGION_DECO_ALT.
- 타일 레이어(기본 · 풀 · 벽 · 벽 장식 · 광원/효과 · 전경), 함정 오브젝트(게임 함정 규칙 그대로), 조합 타일 · 자동 생성 규칙(씨앗 공식 포함), 밑그림 규칙 — 코드 동작 변경 없음 (조합 광원 세이브만 P1-1).
- 기존 세이브 호환: 광원 복사본이 없는 세이브는 이전처럼 지금 정의에서 광원을 찾음(헤드리스로 확인).
- 편집기 UI · 단축키 · 사용 방법 — 바뀐 것 없음. 달라진 점은 알림 문구(손상 파일)와 검사 결과 항목이 늘어난 것뿐.

## 4. 개선한 기능

| 무엇 | 파일 | 효과 |
|---|---|---|
| 손상 파일 구분 · 덮어쓰지 않기 · 손상본 백업 | `store.js load/save` | 쓰다 만 파일 하나로 맵 그래프 · 노드를 잃지 않음 |
| 저장 순서 (백업 → 쓰기 → 지우기), 실패 시 남은 항목 유지 | `store.js save` | 저장 실패가 데이터 손실로 이어지지 않음, 다시 저장 가능 |
| 변환 · 삭제 전 원본 백업 (`.pdmaker-backup`, 20개 보관) | `store.js`, `main.js skipProj` | 변환 · 삭제를 되돌릴 길이 생김. 게임 · 내보내기에는 섞이지 않음 |
| 조합 광원 세이브 고정 | `MakerCombos` | 프리셋 편집이 이미 만든 층을 바꾸지 않음 (문서 정책과 일치) |

| 회귀 테스트 | `tools/tests/` | 표 일치 · 저장 안전성 · 변환 · 검사를 매번 확인 |

## 5. 편집 자유도

이미 있던 것(이번에 게임에서 다시 확인): 레이어 추가 · 순서 · 캐릭터 위/아래 · 게임 표시 · 막힘 · 편집기에서만 숨기기, 같은 칸에 레이어마다 다른 타일, 조합 타일(팔레트에서 스프라이트 고르기 · 겹치기 · 레이어 · 오프셋 · 순서 · 불투명도 · 발광 · 실제 광원 · 이펙트 · 함정/맵 오브젝트 · 미리보기 · 복제 · id 바꾸기 · 삭제 · 쓰는 곳 · 자동 생성 등록/해제 · 위치 조건 · 확률 · 최대 · 간격 · 테마), 함정을 바닥과 별개 오브젝트로, 밑그림 대응표 편집.

이번에 새로 생긴 것: 조합을 마음껏 고쳐도 이미 진행 중인 세이브의 층이 바뀌지 않는다는 보장(광원까지), 검사로 보이는 레이어 데이터 문제. **화면에서 새로 제어할 수 있게 된 편집 기능은 이번에는 없음** — 다중 선택 · 영역 복사 등은 §10 후속 작업.

사용자가 직접 할 수 있는 것 / 코드가 필요한 것: 레이어 · 조합 · 자동 생성 조건 · 밑그림 대응표 · 함정 배치는 편집기에서. 새 자동 생성 위치 조건(`where`)이나 새 오브젝트 종류는 `MakerCombos.fits` · `LevelHooks.placeObject` 와 `schema.js OBJECT_TYPES` 를 고쳐야 함.

## 6. 데이터 호환성

- 기존 프로젝트: 형식 변경 없음. 처음 저장할 때 변환된 파일이 있으면 원본이 `.pdmaker-backup/<시각>/` 에 남음.
- 기존 세이브: 그대로 이어할 수 있음(헤드리스 확인). 새로 만든 층부터 광원 복사본이 붙음.
- 마이그레이션 절차: 따로 할 일 없음 — 열고 저장하면 됨. 되돌리기는 백업 폴더 파일을 같은 경로로 복사.

## 7. 성능

측정한 것: 없음 (아래는 실행 확인뿐).
- 조합 자동 생성: 35×37 하수도 층에서 7~10곳, 층 만들기 지연은 체감되지 않음(측정 안 함). 후보 탐색은 조합마다 칸 수 O(N), 간격 확인은 놓인 수에 비례.
- 측정이 필요한 곳: 맵 편집기 큰 맵 그리기(P3-3), 레이어 · 그림 묶음이 많을 때 게임의 CustomTilemap 수(묶음 = 레이어 × 그림 × 오프셋/불투명도 조합마다 하나), 밑그림 굽기(층마다 타일셋 크기 픽셀 순회 1회).

## 11.3 편집 기능 (조작법)

맵 편집기 도구 막대 **⇱ 선택**(M):
- **영역**: 빈 칸에서 끌기 — 어느 방향이든, 맵 밖으로 끌면 맵 경계까지. 오브젝트 칸에서 시작하려면 **Alt+끌기**(그냥 끌면 예전처럼 그 오브젝트를 옮김). 끌지 않고 누르면 선택 해제. **Ctrl+A** = 맵 전체.
- **Ctrl+C** 복사 · **Ctrl+X** 잘라내기 · **Ctrl+V** 붙여넣기: 노란 점선 미리보기가 마우스를 따라다니고 누른 칸이 왼쪽 위가 됨. 계속 누르면 여러 번 붙음(반복 배치). 오른쪽 클릭 · Esc = 끝. 다른 맵 · 방 템플릿에도.
- **Delete** = 영역 비우기(지우개 "전부"와 같음). 속성 창: 복사 · 잘라내기 · 복제… · 비우기 · 선택 해제.
- **여러 오브젝트**: Shift 또는 Ctrl+클릭으로 더하기 · 빼기(영역을 끌면 영역 안 오브젝트도 함께 고름). 고른 것 중 하나를 끌면 모두 함께 이동, 방향키 한 칸(Shift = 5칸). 하나라도 맵 밖으로 나가면 아무것도 옮기지 않음. 속성 창에서 공통 속성 일괄 수정 · 복제… · 삭제.
- 모든 작업은 실행 취소(Ctrl+Z) · 다시 실행(Ctrl+Y) 한 번 단위.

붙여넣기 규칙(빈 칸 · 레이어 · 맵 밖 · id · 참조): DESIGN §4.3 "영역 · 여러 오브젝트". 요약 — 원본 빈 칸은 투명, 나머지 칸은 지형 · 레이어(빈 레이어 칸 포함)를 원본대로, 맵 밖은 붙이지 않고 알림, 오브젝트는 새 id + 좌표만 바뀜, 받는 자리의 기존 오브젝트는 지우지 않음, 무작위 칸은 같은 맵에서만, 방 템플릿에는 노드 전용 오브젝트를 붙이지 않음.

## 11.4 데이터 안전성

- 선택 · 미리보기는 화면 상태에만 — 데이터를 바꾸지 않음. 붙여넣기는 `mapArea.valid` 로 모양을 확인한 뒤에만, 지형 배열이 크기와 맞지 않는 맵에는 붙이지 않고 오류. 잘라내기는 복사본이 올바를 때만 지움.
- 복사본은 깊은 복사 — 붙여넣기가 클립보드 · 원본 맵을 바꾸지 않음(테스트).
- 검사는 읽기만 함: 테스트가 검사 전후의 모든 파일(크기 · 시각 · 해시)과 데이터 JSON 이 같음을 확인. 손상된 파일은 오류로 보여 주고 파일은 그대로(1차 정책 유지).
- 실행 취소 메모리: 영역 편집도 기존 편집과 같이 노드 JSON 스냅샷 두 개(전 · 후) — 새로 늘어난 비용 없음(80×80 · 레이어 몇 개면 한 번에 수백 KB, 최대 200단계).

## 11.5 호환성

- 파일 형식: 바뀐 것 없음. 새 키는 `tilecombos.json autogenVersion`(새로 만드는 파일에만 2) · 조합 `autogen.priority`(버전 2 에서만 읽음) · 클립보드 kind `maparea`(파일에 저장하지 않음).
- 예전 조합 파일(값 없음)은 열고 저장해도 버전이 바뀌지 않음(테스트). 버전 1 에서 같은 씨앗 `PDMTEST` 의 1층 배치 = 1차 작업 때 이전 런타임으로 얻은 배치와 같은 10곳 · 광원 10 (헤드리스 게임).
- 기존 단축키: 바뀐 것 없음. Ctrl+X 는 새 전역 동작이지만 처리할 탭(맵 편집기)이 아니면 브라우저 기본 그대로, 스프라이트 편집기는 먼저 처리하므로 그대로. Ctrl+A · 방향키 · Alt+끌기는 맵 편집기 안에서만.
- 오브젝트를 끌면 옮기는 예전 동작, 오른쪽 클릭 메뉴, 단일 오브젝트 복사(kind `mapobj`) · 붙여넣기 그대로.
- 보존 타일 번호 29종 · DungeonTileSheet 대응 · 함정 배치/발동 · 조합 광원 세이브 고정: 테스트 · 게임으로 다시 확인(§11.6).

## 11.7 미검증 항목

- Electron 창에서의 조작(테스트는 같은 화면 코드를 웹 모드 브라우저로 돌림 — 시스템 클립보드 권한 · 메뉴 표시는 Electron 에서 확인 안 함). Windows · macOS(대소문자를 구분하지 않는 파일 시스템에서 "대소문자" 경고가 나오는지는 폴더 목록 비교라 같은 결과일 것으로 보지만 실행하지 않음).
- 태블릿 펜 · 터치로 영역 끌기. 큰 붙여넣기(맵 전체 80×80)를 여러 번 했을 때의 실행 취소 메모리 측정.
- 안드로이드 빌드 · 게임 내보내기.

## 11.8 잔여 위험

- 붙여넣기 미리보기는 지형 · 오브젝트 자리만 그림 — 타일 레이어 그림은 미리보기에 없음(붙인 뒤에는 보임).
- 맵 밖으로 나가는 붙여넣기는 잘림(맵을 넓히지 않음) — 알림으로만 알려 줌.
- 오브젝트 칸에서 그냥 끌면 오브젝트 이동(예전 동작 보존) — 영역은 빈 칸에서 시작하거나 Alt+끌기. 처음 쓰는 사람은 헷갈릴 수 있음(도구 설명 · 팔레트 안내 · 단축키 창에 적음).
- 버전 2 로 바꾸면 그 프로젝트의 새 층 자동 생성 배치가 한 번 바뀜(확인 창으로 알림, 이미 만든 층 · 세이브는 그대로).
- 맵 편집기 그리기는 여전히 매번 전체 다시 그리기(P3-3) — 80×80 ×2 에서 이동 한 번 약 25~38ms. 더 큰 확대 · 느린 PC 에서는 끌기가 무거울 수 있음.
- 편집기 · 런타임 중복 표는 테스트로만 묶여 있음.

## 11.9 편집기 · 런타임 중복 표 — 단일 원본 분석

현재 중복: `TILE_LEGACY_DEFAULT` · `TILE_HOLES` · `TILE_LAYERS_DEFAULT` · `TRAP_LEGACY`(+ 이번의 자동 생성 위치 목록 `WHERE`). 선택지:
1. **생성 스크립트** — 이미 쓰는 방식(`tools/data/gen_terms_java.js` → `DefaultTerms.java`)과 같게 `tools/data/gen_tables_java.js` 가 `schema.js` 값으로 `MakerTables.java` 를 만듦. 런타임 설치 · 빌드 방식이 바뀌지 않아 가장 안전. 단점: 생성을 잊으면 어긋남 → 지금의 표 일치 테스트가 그대로 지켜 줌.
2. 런타임이 JSON 을 읽게 — `runtime-installer` 가 표 JSON 을 게임 assets 에 넣어야 하고, 오래된 설치본과 섞이면 판이 어긋날 위험. 이번 범위에서는 권하지 않음.
→ 권장: 1번 + 기존 테스트 유지. 이번에는 구현하지 않음(기능과 무관한 변경을 줄이려고).

## 11.10 후속 작업 (우선순위)

1. 붙여넣기 미리보기에 타일 레이어 그림 · 맵 밖 칸 표시, 붙여넣기로 맵을 넓히는 선택지.
2. 맵 편집기 그리기 최적화(보이는 칸만 · 지형 캐시) — 이번 측정값을 기준으로 전후 비교.
3. 표 단일 원본(§11.9 의 1번).
4. 영역 이동(잘라내기 + 붙여넣기 없이 영역을 바로 끌기) · 회전 · 뒤집기.
5. Electron 창에서 같은 UI 테스트를 돌리는 방법(Playwright Electron).
