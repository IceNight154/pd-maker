## 1. 발견한 근본 원인

8차까지의 편집기(HEAD `9b52a41`)로 두 저장소를 읽으면, 폴더는 열리지만 다음이 틀리거나 빠졌습니다. 숫자는 이번에 HEAD 코드로 직접 재었습니다 (§4).

### ARK_PD-main

1. **아이템 그림 칸 계산이 틀림.** 편집기는 `items.png` 너비 ÷ 16 으로 칸 크기를 짐작했습니다. ARK 는 `ItemSpriteSheet.java` 에 `SIZE = 32` · `WIDTH = 32` 를 두고 1024px 시트를 씁니다. 짐작한 격자는 64px × 한 줄 16칸이라 그림 번호가 엉뚱한 칸을 가리켰습니다. 아이템 120개를 표본으로 실제 픽셀을 보니, 그림이 있는 칸을 가리킨 것이 예전 격자 79개, 새 격자 117개입니다.
2. **영웅 그림 파일을 못 찾음.** 편집기는 `sprites/<직업>.png` 로 가정했습니다. ARK 는 `HeroClass.spritesheet()` 의 `switch` 로 파일을 고릅니다 (WARRIOR → `sprites/blaze.png` 등). 7명 중 5명이 그림 없음이었습니다. 영웅 칸 크기도 36×36 입니다.
3. **층별 몬스터 목록을 못 읽음.** 편집기는 `actors/mobs/MobSpawner.java` 를 고정으로 읽었습니다. ARK 에서는 같은 일을 `MobRotation.java` 가 합니다. 맵 편집기의 "몬스터 스폰" · 드랍 테이블 "게임 목록 가져오기"가 비었습니다.
4. **새 몬스터에 그림이 없음.** 저장소에만 있는 몬스터 117종이 모두 임시 그림으로 들어왔습니다. 편집기가 몬스터 클래스의 `spriteClass` → 스프라이트 클래스 → `texture(Assets…)` · `TextureFilm` · 애니메이션을 따라가지 않았기 때문입니다.
5. **런타임이 컴파일되지 않는데 "설치 가능"으로 보임.** PDMaker 런타임이 이름으로 부르는 게임 클래스 14개가 ARK 에 없습니다 (`MobSpawner` · `TengusMask` · `KingsCrown` · `ArmorAbility` · `WndChooseAbility` · `PrisonBossLevel` 등 4개 보스 층 · `HeroIcon` · `TalentIcon` · `ui.Button` · `JournalScene` · `ShatteredPixelDungeon`). 설치기의 검사(`compat`)는 연결 줄 위치만 봐서 "설치 가능 · 연결 줄 27개 누락"이라고 했습니다.
6. 그 밖의 구조 차이: `settings.gradle` 이 한 문장에 모듈 9개를 include 함, 게임 시작 클래스가 `TomorrowRogueNight`, 게임 중 영웅 그림이 바뀌는 스킨.

### New-Blue-Archive-Pixel-Dungeon-main

이 저장소는 7 · 8차에 이미 많이 맞춰 두었습니다 (글자 폴더 `messages` + `new_messages`, 원작 6직업 감춤). 남은 것은 다음입니다.

1. **새 몬스터에 그림이 없음.** 24종이 모두 임시 그림이었습니다. 원인은 ARK 의 4번과 같습니다.
2. **원작에서 이어받는 몬스터를 놓침.** 금고(vault) 몬스터 3종처럼 `spriteClass` 를 부모에게서 이어받는 몬스터는 목록에 아예 없었습니다. 기준 저장소도 마찬가지였습니다 (19 → 22).
3. **읽지 못하는 파일을 알리지 않음.** 병합 충돌 표시가 남은 `ios/.../IOSPlatformSupport.java`, 그림 프로그램 원본 `.aseprite` 21개가 그냥 지나갔습니다.

### 공통

- 편집기에는 "무엇을 읽었고 무엇을 못 읽었는지"를 보여 주는 곳이 없었습니다. 몬스터 · 아이템 · 리소스를 못 읽어도 조용히 기본값을 썼습니다.
- 소스를 정규식으로 바로 훑었습니다. 그래서 주석 · 문자열 속 괄호, 안쪽 클래스, `AirborneSprite .class` 같은 공백(ARK) 에서 틀렸습니다.

## 3. 변경한 파일과 설계

### 3.1 읽기 전용 분석과 가져오기를 나눔

```
게임 저장소 (읽기만)
   │  repo-analyzer.js  ── 루트 찾기 → 안전한 훑기 → 빌드 · 모듈 → 게임 모듈 · 패키지 → 소스 구조 → 리소스 디코딩
   │                       → 에셋 참조 → 클래스 관계 → 게임 객체 → 지원 범위 → 런타임 호환        (캐시: 사용자 설정 폴더)
   ▼
분석 결과(JSON) ──► 「게임 저장소 분석」 화면 (repoanalysis.js)
   │
   ▼  gamescan.js (가져오기) — 결과를 PDMaker 리소스 목록 · 프로젝트 캐릭터/영웅으로 변환 (origin 기록)
프로젝트 파일
```

분석기는 저장소에 아무것도 쓰지 않습니다. 쓰는 곳은 캐시 폴더 하나(`userData/repo-analysis/`)뿐입니다. 테스트가 분석 · 변환 전후의 저장소 지문(파일 목록 · 크기 · 수정 시각)이 같은지 확인합니다.

### 3.3 구조 차이 → 어댑터

분석기는 폴더 이름이 아니라 소스에서 차이를 찾고(`features[]`), 차이마다 근거(파일 · 줄)와 처리 방식을 적습니다. 저장소 이름으로 분기하는 코드는 없습니다.

| id | 찾는 방법 | 처리 |
|---|---|---|
| `item-sheet-geometry` | `ItemSpriteSheet` 의 `SIZE` · `WIDTH` | 편집기 `assets.itemGrid` 가 이 격자로 그림 번호 → 칸 계산 |
| `hero-sheet-switch` | `HeroClass.spritesheet()` 의 `switch(this)` → `Assets` 상수 → 실제 파일 | 영웅 그림을 실제 파일로 연결, 예전 프로젝트의 잘못된 경로도 "맞추기"로 고침 |
| `hero-frame` | `HeroSprite` 의 `FRAME_WIDTH` · `FRAME_HEIGHT` | 영웅 칸 크기 |
| `hero-skin` | `spritesheet()` 가 `Dungeon.hero` 값으로 고름 | 기본 시트만 연결 · 스킨은 미지원으로 표시 |
| `mob-rotation-class` | `standardMobRotation(` 이 있는 클래스 | 맵 "몬스터 스폰" · 드랍 테이블이 그 파일을 읽음 |
| `messages-overlay` | `Assets` 의 `<폴더>/<묶음>/<묶음>` 상수 | 모든 글자 폴더에서 이름 · 설명 읽기 |
| `settings-single-include` | include 문장 하나에 모듈 여럿 | 보고만 (런타임의 android 건너뛰기 줄이 들어가지 않음) |
| `game-class` | `extends Game` 인 클래스 | 보고만 |
| `kotlin` | `.kt` 파일 | 목록만 · 분석 미지원으로 표시 |

### 3.4 소스 · 리소스 분석

- **소스**: 모든 Java 파일을 구조 분석합니다. 괄호 짝이 안 맞거나 병합 충돌 표시가 남은 파일은 실패, 파일 이름 · 패키지 위치가 다르면 부분 성공입니다. 줄 번호를 같이 남깁니다.
- **게임 객체**: 상속 관계 그래프로 찾습니다 (`Mob` · `Item` · `Room` · `Level` · `Buff` · `Plant` · `Trap` · `Blob` · `CharSprite` …). 필드 값은 자기 본문 → 부모 순서로 찾고, 부모에게서 온 값은 출처를 적습니다 (예: `stats.from.exp = 'Blob'`).
- **스프라이트**: `spriteClass` → 스프라이트 클래스(안쪽 클래스 포함) → `texture(Assets…)` · `TextureFilm` · 애니메이션 → 그림 파일 · 크기 → 프레임 번호가 그림 안에 있는지까지 봅니다. 코드로 고르는 그림(`spriteClass = Status.getSprite()`)은 변환은 하되 "코드로 고름"이라는 이유와 함께 임시 그림을 씁니다.
- **리소스**: PNG 는 끝까지 풉니다 (청크 CRC · 압축 · 줄 길이). JPG · OGG · MP3 · WAV · 글꼴은 머리와 서명을 봅니다. 확장자와 실제 형식이 다르면 실패로 적습니다 (ARK: `.mp3` 인데 WAV 인 파일 11개, `.ogg` 인데 WebM 인 `theme.ogg`). libGDX 의 느슨한 JSON 은 성공으로 칩니다. `.aseprite` 같은 그림 원본 · 형식을 확인하지 않은 파일은 변환하지 않고 경로만 보존합니다. 백업 파일은 "게임이 읽지 않음"으로 둡니다.
- **참조 관계**: `Assets` 상수 · 소스의 문자열 경로를 실제 파일과 맞춥니다. 결과는 확인됨 · 없는 파일 · 대소문자 다름 · 해석 못 한 동적 경로 · 추정 미사용 · 같은 내용 파일로 나눕니다. "추정 미사용"은 오류로 보지 않습니다.
- **안전한 훑기**: 저장소 밖을 가리키는 링크 · 순환 링크 · 깨진 링크 · 권한 오류를 건너뛰고 모두 기록합니다. 긴 Windows 경로(`\\?\`) · 한글 · 공백 경로, 대소문자만 다른 파일도 처리합니다. 빌드 결과 폴더는 훑지 않습니다.
- **루트 찾기**: `settings.gradle` 이 있는 폴더를 씁니다. 모듈 폴더(`core` 등)를 고르면, 위 폴더의 `settings.gradle` 이 그 폴더를 포함할 때만 올라갑니다. 저장소가 여럿 든 폴더(`game/`)를 고르면 첫 폴더를 고르지 않고 후보를 보여 줍니다.
- **런타임 호환**: 설치기의 연결 줄 검사에 더해, 런타임이 이름으로 부르는 게임 클래스 164개가 저장소에 있는지 봅니다 (모든 모듈). 없으면 "설치는 되지만 컴파일 안 됨"으로 보이고, 클래스와 쓰는 곳(`MakerRuntime.java:384` 등)을 보여 줍니다. 메서드 모양까지는 보지 않으므로, 클래스가 다 있어도 "빌드는 테스트 플레이에서 확인"이라고 적습니다.
- **캐시**: 지문 = 분석기 판 + 런타임 소스 목록 + 저장소 파일 목록 · 크기 · 수정 시각. 하나라도 바뀌면 다시 분석하고, 깨진 캐시는 버립니다. 「다시 분석」은 캐시를 쓰지 않습니다.

### 3.5 PDMaker 내부 모델로 변환 (gamescan.js)

- 새 몬스터는 분석기 결과로 만듭니다. 그림 시트 · 프레임 · 애니메이션 · 체력 · 회피 · 경험치는 원본에서 뽑은 값입니다. 캐릭터에 `origin` 을 남깁니다: `{ repo, file, line, extracted: ['name', 'desc', 'stats.hp', …, 'sprite'], sprite }`. `extracted` 에 없는 값은 PDMaker 기본값입니다. 이렇게 원본에서 뽑은 값과 PDMaker 가 채운 값을 구분합니다.
- 영웅은 실제 시트로 연결하고 `origin` 을 남깁니다. 예전 프로젝트의 `game:sprites/<직업>.png` 는 "영웅·캐릭터를 저장소에 맞추기"가 실제 시트로 고칩니다 (되돌리기 가능).
- 편집기가 모르는 필드는 저장 · 다시 열기 · 고치기 · 저장을 거쳐도 남습니다 (테스트로 확인).
- 다시 맞춰도 중복이 생기지 않습니다 (두 번째 맞추기 = 추가 0 · 삭제 0).
- 일부러 빼는 것: 추상 클래스, 자기 그림 없이 다른 몬스터가 이어받기만 하는 바탕 클래스, 다른 클래스 안의 클래스(`Outer$Inner`). ARK `miniboss.Shadow` 가 바탕 클래스입니다. 게임은 안쪽 클래스 `Shadow.TypeBlaze` 등만 내보내고 `Shadow` 는 도감 묶음 이름으로만 씁니다. 뺀 것은 분석 화면 "게임 객체"에 이유와 함께 남습니다.

### 3.6 「게임 저장소 분석」 화면

열기: 설정 메뉴(⚙ ▾) › 게임 저장소 분석, 또는 프로젝트 설정 › "저장소 분석 보고서".

화면 구성:

- **요약**: 루트 · 고른 이유 · 게임 모듈 · 패키지 · 시작 클래스 · 빌드 · 모듈, 소스 · 리소스 · 게임 객체 숫자
- **구조 차이**: 근거와 처리 방식
- **지원 범위**: 항목 × 8단계 (§5)
- **게임 객체**: 영웅 · 몬스터 · 아이템 · 방 · 층 · 버프 · 식물 · 함정 · Blob 탭
- **문제 목록**: 분석 오류 · 소스 실패 · 디코딩 실패 · 없는 파일 · 대소문자 · 경고 · 미지원 · 게임이 읽지 않는 파일 · 동적 경로 · 추정 미사용 · 같은 내용 · 훑지 않은 링크
- **게임 런타임 설치**

줄을 누르거나 Enter 를 치면 파일 전체 경로, 줄, 원인을 보여 줍니다. 텍스트 파일이면 그 줄 근처 코드도 나오고, "폴더에서 보기"를 누를 수 있습니다.

「다시 분석」은 캐시 없이 분석하고 리소스 목록도 다시 맞춥니다. 같은 내용이 쌓이지 않습니다. 「다른 폴더 분석…」은 프로젝트 설정을 바꾸지 않고 분석만 합니다. 「보고서 저장 (JSON)」도 있습니다.

> 편집기의 `tips.js` 는 `.hint` 글을 ⓘ 말풍선으로 숨깁니다. 처음 만든 화면에서는 구조 차이의 근거 · 처리, 기준 저장소의 "차이 없음", 빈 묶음의 "없음"이 화면에 보이지 않았습니다. UI 테스트에서 이것을 찾았고, 값 · 근거는 `.ra-note`(항상 보임)로, 설명문만 `.hint` 로 나눴습니다.

**사용자 PC 의 작업 폴더에서 `run.js` 를 돌리면 59개 중 4개가 실패합니다.** 원인은 두 가지이고, 이번 변경과 상관없습니다.

- Windows 체크아웃이 `map.js` · `MakerCharAI.java` 를 CRLF 로 바꿔 두어, 줄 끝을 LF 로 가정한 테스트 2개가 실패합니다. 같은 파일은 HEAD 와 내용이 같고, 저장소에는 LF 로 들어 있습니다.
- VM 에 javac 가 없어 2개가 실패합니다.

같은 커밋을 LF 로 받은 클라우드에서는 59개 모두 통과합니다.

## 7. 실제 빌드 · 실행 여부

- 세 저장소 모두 **gradle 빌드 · 게임 실행은 하지 않았습니다.** 이번 작업은 읽기 · 분석 · 가져오기 범위이고, 게임 런타임 코드는 바꾸지 않았습니다.
- 런타임 호환은 **정적으로만** 확인했습니다: 연결 줄 위치와 런타임이 부르는 클래스 이름입니다.
  - 기준 · BA: 164개 모두 있음
  - ARK: 14개 없음 → ARK 에 테스트 플레이(F5)를 하면 런타임 컴파일이 실패합니다. 분석 화면과 지원 범위에 그렇게 나옵니다.
- Electron 창에서 직접 열어 보지는 않았습니다. 같은 화면 코드를 웹 모드 + Playwright 로 확인했고, IPC 가 쓰는 worker 스레드 실행은 Node 에서 같은 방식으로 확인했습니다. 이 확인에서 worker 안에서도 명령줄 처리가 돌아 종료 코드 1 로 끝나던 문제를 찾아 고쳤습니다.
- 실제 저장소 테스트는 사용자 PC 의 원본이 아니라, VM 로컬 디스크에 복사한 사본에서 돌렸습니다 (마운트 경유 읽기가 저장소 하나에 약 50초라 시간 제한을 넘음). 사본은 `build` · `.gradle` 을 뺀 같은 내용이고, 분석기도 그 두 폴더는 훑지 않습니다. 기준 저장소는 원본 경로에서도 한 번 분석해 같은 결과를 얻었습니다.

## 8. 데이터 손실 위험 · 제한 사항

- **ARK 런타임**: 런타임이 쓰는 클래스 14개가 없어 컴파일되지 않습니다. 분석 · 편집 · 저장은 되지만 테스트 플레이 · 게임 파일 내보내기는 안 됩니다. 고치려면 런타임에 "클래스가 없을 때의 대체 경로"(리플렉션 또는 저장소별 생성 코드)가 필요합니다. 다음 회차 과제로 남깁니다.
- **제한된 구조 분석**: 완전한 Java 파서가 아닙니다.
  - 필드 값은 `HP = HT = 숫자` 같은 리터럴만 읽습니다. 계산식 · 메서드로 정하는 값은 "없음"(null)으로 두고 PDMaker 기본값을 쓰며, `origin.extracted` 에 넣지 않습니다.
  - 그림을 코드로 고르는 스프라이트는 임시 그림을 씁니다 (분석 화면에 이유가 나옴).
  - 같은 이름의 클래스가 여럿이면 같은 파일 → 같은 폴더 → 첫 번째 순서로 고릅니다 (`ambiguousNames` 에 목록).
- **모델이 없는 것**: 버프 · 식물 · 함정 · Blob 은 원본 참조(파일 · 줄 · 부모)만 보존합니다. 파생작 고유 지역(ARK 층 30개 중 원작 5지역 밖)은 테마로 바꾸지 않습니다. 영웅 스킨 시트는 기본 시트만 연결합니다.
- **원본 보존**: 분석 · 가져오기는 원본 저장소에 쓰지 않습니다 (지문으로 확인). 프로젝트 쪽에서는 `origin` 과 모르는 필드가 저장을 거쳐도 남습니다. 다만 "영웅·캐릭터를 저장소에 맞추기"는 저장소에 없는 원작 캐릭터 · 영웅을 프로젝트에서 뺍니다 (예전과 같은 동작, 실행 취소 가능). ARK 에 맞추면 원작 캐릭터 20 · 영웅 2가 빠집니다.
- **캐시**: 파일 크기 · 수정 시각으로 바뀜을 봅니다. 크기와 수정 시각을 그대로 둔 채 내용만 바꾸면 놓칠 수 있습니다. 「다시 분석」은 항상 새로 읽습니다.
- **목록 길이**: 보고서 목록은 종류마다 400개(소스 문제 200개)까지만 담고 전체 개수를 함께 표시합니다.
- **ARK 의 소리 파일**: 형식이 다른 소리 11개는 원본 문제입니다. PDMaker 는 고치지 않고 알리기만 합니다.
