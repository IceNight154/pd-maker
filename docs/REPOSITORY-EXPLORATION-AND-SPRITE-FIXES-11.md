## 1. 각 스프라이트 문제의 재현 절차와 근본 원인

**재현 환경**
- `tools/playtest/repo-project.js <저장소> <폴더>`로 편집기의 새 프로젝트와 같은 과정을 밟아 프로젝트를 만듭니다: 분석 → 저장소에 맞추기 → 맵 기본 표시 → 저장.
- `tools/playtest/build.sh`로 저장소 사본에 런타임을 설치하고 컴파일합니다.
- 헤드리스(Xvfb)로 실행합니다.
- 비교 기준은 **런타임을 넣지 않은 원본 ARK**입니다. `git archive`로 만들고 같은 검사 도구만 넣었습니다.

**검사 명령** (`tools/playtest/Hooks.java`)

| 명령 | 출력 |
|---|---|
| `eval:selicons` | 선택 버튼 아이콘의 텍스처 · 프레임 · 크기 |
| `eval:herosprite` | 게임 중 영웅의 텍스처 · 프레임(픽셀) · 그리는 크기 · 칸 대비 · 게임 코드 여부 |
| `eval:imgstat` | 화면의 모든 그림의 크기 · 배율 · 텍스처 · uv |
| `eval:changeclick,<n>` | 변경 사항 화면의 n번째 버튼 정보를 찍고 누름 |

### ① 영웅 선택창에서 모든 영웅이 갑옷 최대치 모습

**재현:** 테스트 플레이 → 영웅 선택.
- 수정 전 버튼 아이콘은 `HeroRuntime.avatarOf(h, 6)`이었습니다. 시트의 6번 줄(직업 갑옷), 0번 칸을 20px로 줄인 그림입니다.

**원본:** ARK `HeroSelectScene.HeroBtn`은 직업마다 `icon(new Image(Icons.BLAZE.get()))`처럼 **얼굴 아이콘**을 씁니다 (`interfaces/icons.png` (0,128)–(20,148) 등).
- 원작 SPD는 `new Image(cl.spritesheet(), 0, 90, 12, 15)`(6번 줄)입니다.
- BA는 `new Image(cl.spritesheet(), 0, 0, 12, 17)`(0번 줄)입니다.

**근본 원인:** PDMaker 선택 화면이 게임 버튼 대신 자기 버튼을 만들면서 원작 SPD의 규칙(6번 줄)을 모든 저장소에 적용했습니다.
- 처음 어긋난 단계는 **런타임**(`HeroSelect.icon`)입니다.
- 분석기도 아이콘 출처를 읽지 않았습니다.

### ② 게임 중 영웅이 너무 작음

**재현:** ARK 테스트 플레이 → 1층.
- 수정 전 데이터는 `sprite.frame = [36,36]`, `scale 0`, 동작은 원작 기본(idle 0,0,0,1…)이었습니다.
- 그 결과 `15/36` 배율로 줄어 32px 칸에 약 15px로 그려졌습니다. 동작 번호도 원작 것이라 0번(초상화) 칸이 나왔습니다.

**원본:** ARK `HeroSprite`

| 항목 | 값 |
|---|---|
| `tiers()` | `new TextureFilm(texture, texture.width, FRAME_HEIGHT=36)` → 갑옷 한 줄 36px |
| `updateArmor()` | `new TextureFilm(tiers(), tier, 36, 34)` → 그 줄 안의 36×34 칸 |
| idle | 41–48 (30프레임 @7fps) |
| run | 1–8 @20 |
| die | 26–36 @8 |
| attack | 9–17 @22 |
| Sattack | 9,11,14,16 @15 |
| operate | 37,38 |
| fly | 39,40 |
| read | 18–25 |
| zap | attack 복사 |
| 배율 | 지정하지 않음 → 원래 크기 |

- 시트는 1800×288(8줄 × 50칸)입니다. 타일은 `DungeonTilemap.SIZE = 32`입니다.

**근본 원인:** 분석기가 `FRAME_WIDTH · FRAME_HEIGHT` 상수만 읽었습니다.
- 그래서 줄 높이 36과 칸 높이 34를 구분하지 못했고, 동작 번호와 배율을 몰랐습니다.
- 처음 어긋난 단계는 **분석기**입니다. 이어서 "칸이 24px보다 크면 15px로 줄임"이라는 **런타임 규칙**이 겹쳤습니다.

### ③ 소개 · 변경 사항 화면의 그림 크기 · 비율 · 잘림

**재현:** 테스트 플레이 → 타이틀 → 소개 → 뒤로 → 변경 → "Recent Changes"(현재 변경 사항) → 항목 누르기.

**재현 과정**
1. 저장소에서 갓 만든 ARK 프로젝트로는 원본과 **같았습니다**.
   - 소개 화면 그림 30개, 변경 사항 93개, 항목 창 97/97개를 비교했고 모두 `imgstat`로 똑같았습니다.
   - 따라서 영웅 초상화 연결 줄, 아이템 그림 합치기, 타이틀은 원인이 아닙니다. 아이템 그림 합치기는 프로젝트 아이템 PNG 2개(16px · 64px)를 넣어 확인했고, 칸 픽셀 좌표가 같았습니다.
2. 남은 경로는 프로젝트의 **게임 그림 바꾸기**(`assets/game/<게임 경로>.png`)였습니다.
   - 그림 관리 › "고치기", 타이틀 편집기의 icons · chrome, UI 테마, 배지 편집기가 원작 SPD 저장소의 원본을 프로젝트로 복사합니다.
   - 원작 `interfaces/icons.png`(256×128)과 `sprites/items.png`(256×512)를 넣고 ARK로 실행하자 재현됐습니다. ARK 원본은 256×256과 1024×1024입니다.
   - 원본과 다른 그림이 **264개**였습니다. 변경 사항 창의 아이콘이 엉뚱한 칸에서 잘리고 길게 늘어났습니다.

**근본 원인:** 런타임 `MakerAssets.install`이 바꾼 그림의 크기를 확인하지 않고 게임 텍스처를 통째로 갈아 끼웠습니다.
- 게임은 그림을 **픽셀 칸**(`TextureFilm` · `uvRect`)으로 자르므로, 크기가 다른 시트에서는 다른 곳이 잘립니다.
- 처음 어긋난 단계는 **런타임**입니다. 편집기도 이 상황을 알리지 않았습니다.

## 2. 원본 게임의 스프라이트 구조와 수정 내용

**분석**
- `javasrc.heroSprite`가 `HeroSprite.java`를 읽습니다.
  - 칸: `updateArmor()`의 `TextureFilm(tiers(), 단계, W, H)`. `spearForm` 같은 다른 분기의 칸은 쓰지 않습니다.
  - 갑옷 줄 높이: `tiers()`.
  - 동작: `x = new Animation(fps, loop)` + `x.frames(film, …)`, `zap = attack.clone()`. 상수와 식을 계산합니다.
  - 배율: `scale.set`. 없으면 1입니다.
  - 근거: `evidence`에 문장을 그대로 남깁니다.
- `javasrc.heroSelectIcons`는 `HeroSelectScene.HeroBtn` 생성자의 `switch`에서 직업별 아이콘 출처를 읽습니다. `Icons.X` 또는 시트 칸입니다.
- 분석기(VERSION 4)는 `objects.heroSprite`와 `objects.heroSelectIcons`를 냅니다.
  - 기능 목록에는 `hero-tier-rows`와 `hero-select-icons`를 냅니다.
  - `heroFrame`은 이제 실제로 자르는 칸입니다.

**프로젝트로 옮김** (`reposync.heroWant`, 출처 기록)

| 칸 | 값 · 출처 |
|---|---|
| `sprite.frame` | 칸 (repo) |
| `sprite.rowH` | 갑옷 줄 높이 (repo) |
| `sprite.anims` | 동작 (repo) |
| `sprite.scale` | 배율 (`scale.set`이 없으면 derived = 1) |
| `select.iconTier` | 시트 칸이면 그 줄(repo). Icons 얼굴이면 0(derived — 시트를 바꾼 경우에만 씀) |

- 원작에 없는 직업(ARK의 CHEN 등)은 예전에 원작 영웅의 동작과 배율을 본떠 만들어졌습니다. 그 값이면 "기본값"으로 보고 바꿉니다.
- 사용자가 고친 값은 그대로 두고 충돌로 표시합니다 (`legacyHero`).

**런타임**
- `HeroRuntime.nativeSprite(h)`: 영웅의 `sprite.*` 칸이 모두 출처 기록(repo/derived)과 같으면 **게임 `HeroSprite` 코드가 그립니다**.
  - `updateArmor`, 초상화, 저장 슬롯 초상화가 모두 게임 코드입니다.
  - 그래서 ARK의 스킨(`CharSkin`), 니어 `spearForm`, `Sattack`이 원본처럼 동작합니다.
  - 칸 하나라도 고치면 PDMaker가 그립니다.
- PDMaker가 그릴 때:
  - `sprite.rowH`가 칸 높이와 다르면 게임처럼 `TextureFilm(TextureFilm(tex, tex.width, rowH), 줄, W, H)`로 줄 안에서 자릅니다.
  - `scale > 0`이면 그 배율을 씁니다. 0이면 예전 자동 축소입니다(예전 프로젝트 호환).
- 선택 버튼(`HeroSelect.icon`):
  - 시트가 바탕 직업의 게임 시트 그대로면(`gameSheet`) 게임 `HeroSelectScene$HeroBtn(직업)`을 만들어 그 아이콘을 복사합니다. 원작 · ARK · BA의 서로 다른 규칙을 게임 코드가 정합니다.
  - 시트를 바꾼 영웅은 그 시트의 `select.iconTier` 줄 첫 프레임입니다. 기록이 없으면 원작처럼 6입니다.
  - 다른 영웅의 그림은 보이지 않습니다. 시트를 바꾼 아미야는 바꾼 시트의 그림입니다.

**게임 그림 바꾸기:** `MakerAssets.sizeOk`가 다음을 처리합니다.
- `assets/game/<경로>.png`의 크기(PNG 머리말)가 이 게임 원본과 다르면 쓰지 않고 경고합니다.
  - 테스트 플레이 출력과 게임 로그에 `게임 그림 바꾸기 건너뜀: … 256×128 인데 이 게임의 원본은 256×256`처럼 나옵니다.
- 통째로 그리는 `splashes/`와 원본에 없는 새 경로는 그대로 씁니다.
- 편집기에서는 그림 관리 카드("⚠ 256×128 ≠ 이 게임 원본 256×256 — 게임에서 쓰지 않음")와 에셋 검사(F7, 종류 "게임 그림 크기")에 같은 내용이 나옵니다.

## 5. 맵 그래프 자동 발견 방식

**언제 도는가:** 분석이 성공했을 때만 `PDM.repoMaps.autoSync()`가 돕니다.
- 프로젝트를 열 때 (`resolveRepo`)
- 저장소를 바꿀 때 (`setRepo`)
- 새 프로젝트를 만들 때

**autoSync가 하는 일**
- 원작에 없는 층 클래스(`extra`)를 **가져오기 버튼 없이** 그래프 그룹 "게임 저장소 맵 — <저장소>"에 넣습니다.
- 원작과 같은 층 클래스는 프로젝트의 기본 층 노드(하수도 1층 …)가 대신합니다(`represented: chain`). 따로 만들지 않습니다.

**중복 · 보존**
- 노드 id는 클래스 · 깊이 · 갈래에서 정해지므로 다시 돌려도 0개를 더합니다.
- 같은 층 클래스를 쓰는 사용자 노드(`gameLevel`)가 있으면 겹쳐 만들지 않습니다.
- 사용자가 지운 저장소 맵은 `world.repoMaps[프로파일].seen`으로 기억해 다시 넣지 않습니다.

**사라진 맵:** 그 프로파일로 가져왔는데 지금 저장소에 없는 노드는 지우지 않습니다.
- 리소스 › 게임 저장소의 맵 › "저장소에 없는 맵"에 보입니다. 타일을 고쳤으면 "(타일을 고침)"이 붙습니다.
- 확인 창에서 고른 것만 `sync({ remove })`로 지웁니다.

**원자성:** 계획(`plan`)을 먼저 만들고(store 그대로) 한 트랜잭션으로 적용합니다.
- 중간에 실패하면 새 노드를 지우고 고친 노드와 그래프를 전 상태로 되돌린 뒤 오류를 알립니다.
- 시험에서 일부러 실패를 일으켜 확인했습니다: 노드 목록 · 그래프 JSON이 같았습니다.

**기록:** 노드 `src`에 다음을 남깁니다.

| 칸 | 내용 |
|---|---|
| `mapTypes` | fixed · partial · game-generated · procedural, 조건이 있으면 + conditional |
| `editable` | `tiles`(고정 맵 → 직접 그리기 노드) 또는 `meta`(이름 · 그룹 · 연결 · 깊이만) |
| `evidence` | `Dungeon.newLevel()` 줄 · 층 클래스 · `build()` 파일:줄 |
| `tilesHash` | 가져온 타일의 지문 (사용자 편집 감지) |

## 11. 남은 문제와 후속 작업

- **크기가 다른 게임 그림 바꾸기는 쓰지 않을 뿐 자동으로 고치지 않습니다.** 사용자가 "원래대로" 한 뒤 이 게임 원본으로 다시 "고치기"를 해야 합니다.
  - 원작용으로 그린 수정을 ARK 시트로 옮기는 기능은 없습니다. 격자가 다르면 자동 변환이 위험합니다.
- **PDMaker가 그리는 영웅(그림 칸을 고친 경우)은 게임의 스킨 · `spearForm`을 따르지 않습니다.** 저장소 그대로인 영웅은 게임 코드가 그리므로 해당되지 않습니다.
- `heroSprite`가 이해하는 구조는 `updateArmor()`의 `TextureFilm(tiers(), …)`와 `Animation`/`frames`/`clone` 문장입니다. 코드로 동작을 만드는 포크에서는 읽은 것만 옮기고, 나머지는 원작 기본을 씁니다. 읽지 못하면 `heroSprite = null`이고 예전 동작입니다.
- 맵 연결의 "추정"(게임 기본 계단)은 근거가 깊이 순서입니다. 실제 계단 위치와 조건은 게임 코드에 있습니다.
- 탐색 화면의 번역 검색은 처음 한 번 모든 messages 파일을 읽습니다(원작 약 11만 줄, 1–2초).
- 게임 데이터 탭의 아이템 "편집 가능"은 기준 아이템 목록(`SPD_ITEM_GROUPS`)에 같은 경로가 있을 때만 바로가기를 냅니다.
