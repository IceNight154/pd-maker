## 1. 게임 테마 적용 범위와 우선순위

**게임 UI 테마 = 프로젝트의 인게임 UI 스프라이트 스킨**입니다. 처음 구현은 색 토큰(패널 · 테두리 · 버튼 색)으로 만들었으나, 요청 의도가 "`chrome.png` · `status_pane.png` 같은 인게임 스프라이트로 만든 UI 의 테마"였으므로 스프라이트 기반으로 다시 만들었습니다.

- **스킨 그림** = 프로젝트의 `assets/game/interfaces/*.png` (`chrome.png` · `status_pane.png` · `toolbar.png` · `menu_pane.png` …).
  - 편집기 「UI 그림」 페이지에서 고치거나 갈아 끼웁니다. 없으면 원작 그림입니다.
  - 런타임 `MakerAssets` 가 게임 그림 자리에 넣습니다 (5차까지와 같은 방식).
  - 원작 창 · 버튼 · 상태 판 · 도구 모음은 원래 이 그림을 쓰므로 그림을 바꾸면 바로 바뀝니다.
- **PDMaker 가 더하는 UI 도 같은 스킨으로** 그립니다 (새로):

  | UI | 그림 | 기본 조각 (`Chrome.Type`) |
  |---|---|---|
  | 대사창 (`MakerDialogue` — 모양 칸이 빈 값 = "게임 UI 스킨") | `chrome.png` 9조각 | `WINDOW` (원작 모든 창) |
  | 이름표 | 〃 | `TOAST_TR` (원작 알림 · 메뉴 단추) |
  | 선택지 · 고른 선택지 | 〃 | `GREY_BUTTON_TR` · `RED_BUTTON` (원작 단추) |
  | 연출 배속 표시줄 바탕 · 배속 단추 · 고른 단추 (`MakerCutscene.Bar`) | 〃 | `TOAST_TR` · `GREY_BUTTON_TR` · `RED_BUTTON` |

  - 조각 좌표는 원작 `Chrome.java` 와 같습니다 (`PDM.gameTheme.CHROME` — `run.js` 가 원작 값과 비교).
  - 어느 조각을 쓸지 = `theme.json` 의 `skin` (UI 마다). 잘못된 이름이면 기본 조각입니다.
  - 그림이 바뀌면 이 UI 들도 함께 바뀝니다. 게임에서 확인: 원작 `chrome.png` 의 빨강 ↔ 파랑을 바꾼 그림을 프로젝트에 넣자 대사창 · 이름표 · 배속 표시줄 · 단추가 모두 새 그림으로 그려졌습니다.
- **글자 색** (그림으로 정할 수 없는 것만) = `theme.json` 의 `colors`:
  - `text` 기본 글자 · `textDim` 보조 · `accent` 강조(창 제목 · 강조 글자 · ▼ · 현재 배속) · `warn` · `error` · `good` · `shadow`.
  - 기본값 = 원작 값 (`Window.TITLE_COLOR` 0xFFFF44 · 회색 0x888888 …).
  - 쓰는 곳: 대사창 글자 · 강조 · 이름 · ▼, 배속 표시줄, 마음 창 · 퀘스트 · 업적 · 상점 · 주문 · 특성 판 · 전직 · 영웅 선택 · 타이틀 하위 페이지의 제목 · 고른 것 · 잠긴 것 · 모자람 · 완료 글자, PDMaker 가 띄우는 원작 모양 창(`WndOptions` · `WndTitledMessage`)의 제목 · 버튼 글자.
  - 바탕 · 테두리 · 버튼 색 토큰은 없습니다. 그 자리는 스프라이트입니다.

**우선순위** (위가 이김):
1. UI 요소에 직접 정한 값 — 대사 한 줄의 강조 색(`emColor`), 대사 스타일 명령, 이름표 · 선택지에 직접 넣은 그림, 대사창 모양을 직접 고름(둥근 상자 · 원작 창 · 내 그림)
2. UI 묶음 설정 — `dialogue.json`. **빈 칸 `""` = 테마를 따름** (모양 빈 칸 = 스킨 조각, 글자 색 빈 칸 = 테마 글자 색)
3. 프로젝트 테마 — `theme.json` (쓸 조각 · 글자 색) + 프로젝트 UI 그림
4. 원작 — 원작 스프라이트 · 원작 글자 색. `theme.json` 이 없으면 런타임 창 글자 색은 그 자리마다 **예전 값 그대로** (`MakerTheme.or(토큰, 예전 값)`)

**예외** (바꾸지 않음):
- 원작이 직접 띄우는 창(가방 · 설정 · 원작 상호작용)의 글자 색은 원작 상수(`Window.TITLE_COLOR`)라 그대로입니다. 틀 그림은 스킨 그림을 따릅니다.
- 타이틀 화면(`title.json`)은 자체 색 · 그림 설정이 있어 그대로 둡니다. "지원" 단추 글자만 accent.
- 영웅 선택 바탕 · 특성 판의 칸 색은 원작 색 그대로입니다 (색 토큰을 없앴으므로).
- HUD 아이콘의 그림 색(마음 아이콘 · 게이지)은 그림 · 데이터 색이라 그대로입니다.

**대비 · 색만으로 구분하지 않기**:
- 편집기가 7쌍의 WCAG 대비를 보여 줍니다. 글자 색 ↔ **그 UI 가 쓰는 조각의 가운데 색**(실제 그림에서 잼, 반투명 조각은 검은 화면 위 색)입니다.
  - 기본(원작 그림 · 원작 글자 색) 7쌍 모두 권장값 이상이고, `run.js` 가 원작 그림에서 잰 값으로 검사합니다.
  - 밝은 조각(예: 두루마리 `SCROLL`) + 흰 글자는 경고로 표시됩니다.
- 고른 배속 단추 · 고른 선택지는 조각(빨간 단추)에 더해 **밑줄**로도 구분합니다.

## 2. 신규 UI가 기본 테마를 상속하는 방식
- **새 프로젝트**(`store.createNew`):
  - `theme.json` 을 만듭니다 (기본 조각 · 원작 글자 색).
  - `dialogue.json` 의 모양 · 글자 색 칸을 빈 값으로 둡니다 (`PDM.defaults.dialogue({ themed: true })`). 대사창이 처음부터 스킨 조각으로 그려집니다.
  - `cutsceneSpeed: true` (내보낸 게임에도 배속 표시줄).
- **예전 프로젝트**:
  - `theme.json` 이 없어도 열고 저장할 때 **만들지 않습니다** (`store` — "쓸 때만 파일").
  - 대사창은 원래 값(둥근 상자 · 직접 색)이 들어 있어 그대로입니다. 런타임 창 글자 색은 `or()` 로 예전 색 그대로입니다.
  - 배속 표시줄은 새 UI 이므로 스킨(기본 = 원작 조각)으로 그려집니다.
  - 편집기 「게임 UI 테마」 화면에 "아직 theme.json 이 없어 예전 모습 그대로" 라고 안내합니다. 값을 고치면 그때 파일이 생깁니다.
- **새 UI 코드**: 바탕 · 틀은 `MakerTheme.patch("UI 이름")` (프로젝트 `chrome.png` 의 그 UI 조각), 글자 색은 `MakerTheme.c(토큰)` 또는 `MakerTheme.or(토큰, 예전 값)` 으로 받습니다. PDMaker 안에서 만든 원작 모양 창은 `GameScene.show` 에서 글자 색을 입힙니다.
- **편집기 「게임 UI 테마」 페이지**:
  - 실제 스프라이트로 그린 미리보기 (대사창 · 이름표 · 선택지 · 배속 표시줄). 프로젝트가 바꾼 `chrome.png` 가 있으면 그 그림입니다.
  - `chrome.png` 전체와 조각 자리 (지금 쓰는 조각은 청록 테두리).
  - UI 마다 쓸 조각 고르기 (작은 미리보기 포함), 글자 색, 대비 목록, 「UI 그림 열기」 단추.
- **대사창 편집기**:
  - 모양 "게임 UI 스킨 (테마)" = 빈 값. 미리보기도 실제 조각으로 그립니다 ("원작 창" 모양도 실제 `WINDOW` 조각).
  - 글자 색 칸 옆 **「테마」** 단추로 빈 값(테마 따름)으로 되돌립니다.
- **실행 중 바꾸기**:
  - 런타임은 1초에 한 번 `theme.json` 의 수정 시각을 보고, 바뀌었으면 다시 읽습니다 (`MakerTheme.version` 증가).
  - 대사창 · 창 · 배속 표시줄은 다음에 만들 때부터 새 값입니다. 그림 파일 자체는 게임을 다시 시작해야 반영됩니다 (원래 동작).

## 3. 배속 표시의 노출 규칙
연출 상태를 **매 프레임 실제 실행 상태에서 다시 셉니다** (`MakerCutscene.why()` — 전역 Boolean 하나로 켜고 끄지 않음):

| 상태 | 근거 |
|---|---|
| 이벤트 시퀀스 | `EventInterpreter` 실행 중 (공통 이벤트 호출 = 같은 실행기의 스택 → 바깥 이벤트가 끝나야 끝) |
| 대사 진행 · 입력 대기 | 대사창 · 원작 모양 대사 창 · 입력 기다리기 창이 떠 있음 (이벤트 밖 대화 포함) |
| 카메라 연출 | `MakerCamera` 가 옮기는 중 · 돌아가는 중 · 흔드는 중 (기다리지 않는 연출이 이벤트보다 오래 남아도) |
| 그 밖 | 플러그인 등의 `MakerCutscene.begin(이유)` → 토큰, `end(토큰)` (토큰마다 따로) |

- **하나라도 있으면 연출 중**: 화면 아래 배속 표시줄이 보입니다.
  - 모양: `▶ 2x` · `1x 2x 4x 16x` · `스킵`.
  - 자리: 대사창이 있으면 그 위(이름표 반대쪽), 없으면 화면 아래 가운데(원작 도구 모음 위). 늘 안전 영역 안입니다.
  - 키: F6 배속 · F10 스킵 (연출 중에만).
- **일반 플레이**: 표시줄이 없고 `Game.timeScale = 1`. 일반 플레이에서는 배속을 바꾸려 해도 무시합니다.
- **표시와 시간은 따로**: 표시줄을 숨기거나 보이는 것은 시간에 영향이 없습니다. 시간은 `MakerCutscene.timeScale()` 한 곳에서만 정합니다 (`run.js` 가 `MakerTestEnv` 에 `Game.timeScale =` 가 없는지 검사).
- **표시줄이 나오는 곳**:
  - 테스트 플레이에서는 늘 나옵니다.
  - 내보낸 게임에서는 `project.json` 의 `cutsceneSpeed: true` 일 때만 나옵니다 (편집기 「게임 UI 테마 › 연출 배속 표시줄」). 예전 프로젝트 = 없음 = 끔.
- 5차의 테스트 플레이 위쪽 배속 단추 줄은 없앴습니다. 테스트용 키 F7 대사 완성 · F8 다음 대사 · F9 화면 돌리기 · F12 디버그는 그대로입니다.

## 4. 이벤트 종료·취소 시 1x 복원 정책
- **연출 상태가 "있음 → 없음"으로 바뀌는 순간 배속 1×, 스킵 끔.** 다음 경우가 모두 포함됩니다:
  - 정상 끝
  - 취소 — 새 게임 · 불러오기 · 멈춘 이벤트 정리 · 게임 화면이 아닌 곳으로 나감
  - 오류 — 명령 실행 중 예외는 기록하고 이어서 끝까지
- 5차의 "스킵 전 배속으로 복원"은 이번 요구대로 **1×** 로 바꿨습니다.
- 게임 화면이 아닌 장면(타이틀 · 층 이동)으로 가면 연출 상태를 지웁니다. 원작도 장면을 바꿀 때 `timeScale` 을 1 로 되돌립니다.
- **중첩**: 공통 이벤트 호출은 같은 실행기 안에서 돌아, 안쪽이 끝나도 바깥이 실행 중이면 연출 중입니다. 게임에서 확인: `event(nest)+dialogue → +camera → event(nest) → +dialogue → 끝`.
- 테스트 플레이 실행 환경의 "시작 배속"은 이제 **연출이 시작될 때의 배속**입니다 (테스트용). 끝나면 여전히 1× 입니다.
- 선택지는 스킵해도 열기만 하고 고르지 않습니다. 입력 기다리기는 그대로 기다립니다 (5차 규칙 유지 — `testenv-check` ③).

## 5. 스크린 이동 (`camMove`)
"카메라 / 스크린" 묶음의 **스크린 이동**. 카메라 가운데를 목표로 옮기고 그 자리에 멈춰 둡니다(HOLD).
- **이동할 곳**:
  - 타일 좌표 — 칸 번호, 0부터, 칸 가운데로. 맵에서 고르기 가능.
  - 월드 좌표 — 게임 픽셀.
  - 캐릭터 · 영웅 — 그 캐릭터의 지금 자리.
  - 이벤트 오브젝트 — 이 맵에 놓인 이벤트. 그림이 있으면 그 NPC, 없으면 그 칸.
- **시간**: 0.1초 단위. 0 = 바로. 음수 · NaN · 무한대 = 0, 최대 60초.
- **보간**: 부드럽게 · 일정한 속도 · 점점 빠르게 · 점점 느리게.
- **도착할 때까지 기다림**: 기본 켬.
- **맵 경계**: 맵이 화면보다 크면 화면이 맵 밖을 보지 않게 자르고, 작으면 그 축은 맵 가운데로 둡니다.
- **화면이 돌거나 커질 때**: 명령의 목표(자르기 전 값)를 새 화면 기준으로 다시 자릅니다. 게임 확인: 모바일 가로 → 세로로 돌려도 왼쪽 위 구석을 보여 줌.
- **없는 캐릭터 · 이벤트**: 기록하고 건너뜁니다 (멈추지 않음).

## 6. 스크린 팔로우 (`camFollow`)
- **대상**: 캐릭터 · 영웅(비우면 영웅), 또는 이벤트 오브젝트.
- **시작**: 지금 자리에서 옮겨 가며, 또는 바로 대상에게.
- **부드럽게 따라감**: 끄면 대상에 딱 붙습니다.
- **세기**: 1초에 남은 거리의 몇 배 (1~30, 원작 영웅 = 5).
- **대상의 화면 자리**: 화면 폭 · 높이의 % (0 = 가운데).
- **중단 조건**: 스크린 리셋, 또는 그 이벤트가 끝날 때. 명령 요약에 "스크린 리셋 · 이벤트가 끝나면 해제"로 보여 줍니다. 기다리지 않는 명령입니다.
- **대상이 없거나 사라짐**: 한 번 기록하고 지금 자리에 멈춰 둡니다 (런타임이 멈추지 않음 — 게임 확인).
- **장면을 다시 만들어도**(회전 · 창 크기) 대상을 id 로 다시 찾습니다.

## 7. 스크린 쉐이크 (`camShake`)
- **칸**:
  - 강도 — 게임 픽셀, 칸 하나 = 16, 0~64
  - 지속 시간 — 0.1초, 비우면 0.5초
  - 흔들림 속도 — Hz, 1~60
  - 감쇠 — 점점 약하게(일정) · 끝에서 부드럽게 · 같은 세기
  - 방향 — 상하좌우 · 좌우 · 상하
  - 끝날 때까지 기다림 — 기본 켬
- **그리기 오프셋만 씀**: 카메라 기본 위치(`scroll`)는 바꾸지 않고, 원작 카메라의 흔들림 칸(`shakeX/Y`, 그리기 행렬만)에 더합니다.
  - 끝나면 오프셋이 **정확히 0** 입니다.
  - 여러 번 불러도 위치가 밀리지 않습니다. 새 쉐이크는 앞의 것을 바꿉니다(더해 쌓지 않음).
  - 게임 확인: 쉐이크 두 번 전후 가운데가 같은 값이었습니다.
- **흔들림 모양**: 정해진 식(사인 두 개)이라 편집기 미리보기와 같습니다.
- **예전 명령 「화면 흔들림」(`shake`)** 은 원작 무작위 흔들림을 그대로 쓰며, 동작을 바꾸지 않았습니다. 기다리지 않고 방향 · 감쇠가 없습니다.

## 8. 스크린 리셋 (`camReset`)
- **돌아가기**: 부드럽게(시간, 비우면 0.5초) · 바로.
- **영웅 따라가기로 돌아감**: 기본 켬. 끄면 영웅 자리에 멈춰 둡니다.
- **다 돌아갈 때까지 기다림**: 부드럽게일 때만 보입니다.
- **정리하는 것**: 흔들림(즉시 0) · 이동 애니메이션 · 팔로우 대상 · 모드. 돌아가는 동안 영웅이 움직여도 그 자리로 갑니다.
- **끝나면**: 원작 따라가기(`panFollow(hero, 5)`)로 넘겨 줍니다. 이전 이동 · 흔들림 타이머가 남지 않습니다 (상태 하나 — 따로 도는 타이머가 없음).
- **자동 정리**:
  - 이벤트가 끝나거나 취소되면, 그 이벤트가 연 카메라 연출을 같은 방식(0.4초)으로 정리합니다.
  - 층 이동 · 새 게임 · 불러오기 = 바로 원래대로.

## 9. 이벤트 명령 속성 및 좌표 단위

| 명령 | 칸 (`events/<id>.json` 의 명령 객체) | 기본값 |
|---|---|---|
| `camMove` | `target` tile · world · char · event, `x` `y` (칸 또는 게임 픽셀), `ref` (캐릭터 id · $hero · 이벤트 id), `time` (0.1초), `ease` smooth · linear · in · out, `wait` | tile (0,0) · 10 · smooth · true |
| `camFollow` | `kind` char · event, `ref` · `event`, `start` pan · snap, `smooth`, `speed` (1~30), `ax` `ay` (화면 %) | $hero · pan · true · 5 · 0 · 0 |
| `camShake` | `power` (게임 픽셀), `time` (0.1초), `freq` (Hz), `decay` linear · smooth · none, `axis` both · x · y, `wait` | 4 · 5 · 12 · linear · both · true |
| `camReset` | `mode` smooth · instant, `time` (0.1초), `follow`, `wait` | smooth · 5 · true · true |

- **좌표**: 월드 = 게임 픽셀. 칸 (x, y) 의 가운데 = (x×16+8, y×16+8). 카메라는 "가운데"로 다룹니다 (화면 크기 · 배율과 무관).
- **편집기 UI**:
  - 고른 설정에 필요한 칸만 보입니다. 예: 이동할 곳 = 월드 → x · y 숫자, 리셋 = 바로 → 시간 · 기다림 숨김.
  - 칸 이름에 단위가 붙습니다. 새 명령은 런타임과 같은 기본값으로 시작합니다 (`defaults`).
  - 검색 · 복제 · 위아래 · 복사/붙여넣기 · 저장/불러오기는 기존 명령과 같습니다 (같은 명령 목록 편집기).
- **직렬화 · 호환**:
  - 기존 형식에 명령 객체 4종을 더했을 뿐입니다. 기존 명령의 동작 · 순서는 바꾸지 않았습니다.
  - 예전 런타임은 모르는 명령을 로그만 남기고 건너뜁니다.
- **완료 대기**:
  - 기다림을 켜면 다음 명령으로 가지 않습니다. 기존 `waitUntil` 이 프레임마다 `MakerCamera` 상태를 확인합니다.
  - 끄면 시작만 하고 이어 갑니다. 이 연출의 수명은 카메라 상태가 관리하며, 이벤트가 끝나면 정리합니다.
- **시간**: 카메라는 원작 카메라 `update` 안에서 `Game.elapsed`(= `Game.timeScale` 이 들어간 시간)로 움직입니다. 2 · 4 · 16배에서 이동 · 쉐이크 · 기다림이 같은 비율로 빨라집니다.
  - 게임 확인: 3초 이동이 1× 에서는 아직 이동 중일 때, 4× 에서는 이미 끝남.
- **미리보기**:
  - 이벤트 「▶ 미리보기」가 맨 뒤 격자(월드)를 `PDM.camera` 식으로 옮기고 흔듭니다. 이 식은 런타임과 같으며 `run.js` 가 비교합니다.
  - 미리보기에는 맵 · 캐릭터 자리가 없어 캐릭터 · 이벤트 대상 이동과 팔로우는 시간만 보여 줍니다.
  - 편집기 맵 데이터는 바꾸지 않습니다. 창을 닫으면 프레임 루프가 멈춥니다.

**카메라 상태 충돌을 막는 방법** (`MakerCamera` — 상태 하나: GAME · MOVE · HOLD · FOLLOW · RETURN):
- **영웅 이동이 덮어쓰기**:
  - 원작은 영웅이 움직일 때(게임 행동 스레드) `panFollow(hero)` 를 부릅니다.
  - 설치기 패치로 원작 카메라 `update` 맨 앞에서 기본 위치를 놓고 원작 따라가기를 끄므로(`synchronized` 한 메서드 안) 같은 프레임에 끼어들 수 없습니다.
  - 게임 확인: 멈춰 둔 동안 영웅을 다른 칸으로 옮겨도 카메라 그대로.
- **이동과 팔로우가 동시에**: 모드가 하나라 마지막 명령만 기본 위치를 정합니다.
- **쉐이크 뒤 위치가 밀림**: 쉐이크는 그리기 오프셋만 씁니다.
- **회전 · 해상도**: 매 프레임 지금 화면 크기로 목표를 다시 자릅니다. 장면을 다시 만들어도 상태(월드 가운데)는 이어집니다.
- **맵 경계 · 작은 맵**: `clampAxis`. 원작의 영웅 따라가기(GAME)는 원작 그대로(제한 없음)입니다.
- **리셋 뒤 이전 애니메이션**: 시간 · 목표가 모두 이 상태에 있어, 리셋이 덮어쓰면 남는 것이 없습니다.
- **배속**: 같은 `Game.elapsed` 를 씁니다.
- **저장 · 불러오기**: 카메라 연출은 저장하지 않습니다. 불러오면 층이 바뀐 것으로 보고 원래대로 돌립니다 (게임 확인).

## 12. 알려진 제한 사항
- **스킨 조각은 `chrome.png` 안에서만 고릅니다**: `status_pane.png` · `toolbar.png` 등은 원작 UI 가 쓰고, 「UI 그림」에서 바꿉니다. PDMaker UI 에 다른 그림 파일의 조각을 쓰는 설정은 없습니다 (대사창 · 이름표 · 선택지는 「내 그림」으로 직접 지정 가능).
- **원작 창의 글자 색은 그대로입니다**: 원작이 직접 띄우는 창(가방 · 설정 · 원작 대화 상자)은 틀 그림만 스킨을 따릅니다.
- **조각 크기**: 그림을 바꿀 때 조각의 자리 · 크기는 원작과 같아야 합니다 (게임이 정해진 자리에서 잘라 씀).
- **실행 중 테마 바꾸기**: 이미 떠 있는 창은 닫고 다시 열어야 새 값입니다. 그림 파일은 게임을 다시 시작해야 반영됩니다. `dialogue.json` 등 다른 파일은 실행 중에 다시 읽지 않습니다 (원래 동작).
- **카메라 미리보기**: 편집기에서는 맵 · 캐릭터 자리 없이 격자 위의 상대 움직임만 보여 줍니다. 실제 경계 · 대상 위치는 테스트 플레이에서 확인합니다.
- **줌**: 카메라 줌 · 구간 고정 같은 확장은 이번 범위에 넣지 않았습니다. 핵심 4개를 먼저 안정화했습니다.
- **카메라 연출은 저장하지 않습니다**: 저장 · 불러오기 뒤 원작 카메라로 돌아갑니다 (이벤트도 저장 시점에 이어지지 않는 원래 동작과 같음).
- **이벤트가 끝나면 카메라도 정리됩니다**: 팔로우 · 멈춰 둔 카메라는 그 이벤트가 끝나면 영웅에게 돌아갑니다. 이벤트 밖에서 계속 유지하는 옵션은 없습니다.
- **배속 표시줄의 자리**: 대사창 위 · 도구 모음 위를 피하도록 계산합니다. 플러그인이 화면 아래에 직접 그린 UI 와는 겹칠 수 있습니다.
- **모바일은 시뮬레이션만입니다**: 실제 터치(멀티 터치 · 길게 누르기) · 실제 노치 · 앱 전환은 확인하지 못했습니다.
